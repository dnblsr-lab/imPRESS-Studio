## [1.7.0] - 2026-09-30

**Print Workflow**: imPRESS Studio becomes the central job system of a print shop. An HTTP server (ASP.NET Core / Kestrel) runs inside the desktop application itself — nothing separate to install — takes jobs and PDFs from a web portal and a REST API, and moves them through preflight, repair, imposition, export and delivery in the background, with the same engines as the desktop export. The shop runs its work from the application's Workflow panel or from any browser on the network. **The server is off by default**: until it is switched on, nothing is created on disk and the application behaves exactly as 1.6.5.

### Added

#### Jobs and workflows
- **Jobs with a lifecycle**: New → Uploading → Preflight → Waiting → Processing → Ready → Completed, with Hold, Error and Rejected. A job carries customer, quantity, pages, page size, paper and grammage, duplex, template, finishing, priority, due date, notes, preflight verdict and approval. Every move is checked against one transition table, applied atomically and recorded with who made it and why. Completed is terminal — a reprint is a new job.
- **A job folder per job**: `Jobs/2026/0001842/` with `original/`, `working/`, `output/`, `reports/`, `thumbnails/` and a `job.json` snapshot. The location is configurable.
- **Workflows**: named production recipes (template, preflight profile, repairs, PDF/X target, engine, ICC profile, cutting guide, auto-preflight, output target, notifications) with rules that pick the workflow for a new job.
- **Workflow modes**: Manual (preflight, then the operator decides), Assisted (preflight, a suggested rule, operator approval, production) and Automatic (preflight, rule matching, production, Ready — with no matching rule the job waits for the operator).
- **Approval**: production can require an explicit approval; producing is refused until then. New artwork or a new preflight clears it. Uploads either start preflight at once or return the job to New for on-demand preflight, per workflow.
- **Processing rules**: conditions (page width/height/size with a 1 mm tolerance, paper format, pages, pages modulo 4, quantity, paper, paper grammage, finishing, duplex, customer, job name, priority, preflight result) and actions (preset, sheet, imposition mode, crop marks, PDF/X export, creep, booklet, repairs, output), with priority and an enable switch. Rules only adjust the inputs of the existing imposition and export engines.
- **The pipeline**: every workflow is a pipeline of ten steps — Input → Preflight → Condition → Repair → Approval → Imposition → Export → Output → Notification → Completion. Condition, Repair and Output can be switched off; the last two are opt-in:
  - **Notification**: a JSON webhook (status, number, name, customer, quantity) when a job becomes Ready, On hold, Error or any chosen status — for an order system, Slack/Teams or a script. One retry; the outcome is logged in the job's history.
  - **Completion**: a job whose files were delivered to a target moves straight to Completed.
- **Background processing**: a queue and 1–8 workers on the thread pool, never on the UI thread. Preflight uses the workflow's profile and template geometry, files the report, reads page count and size from the artwork, applies the workflow's repairs to a copy and renders PNG thumbnails; production imposes the newest repaired copy and exports it. Live progress per job, transient I/O failures retried, anything else ends in Error with the reason. A job is never processed by two workers at once, and work interrupted by a shutdown is recovered on the next start.

#### Output and printers
- **Output connectors**: finished files are delivered to a folder — a RIP's or another hot folder's input — written under a temporary name and renamed when complete, never overwriting anything. Targets are configured in Settings → Workflow Server → Output targets, with `workflow output add`, or by an administrator in the portal's Administration page; everyone else on the web only ever sees their names and printer states.
- **Printers**: a printer is an output target like a folder, so workflows, rules and the Output step print without any other change. Three ways to reach one:
  - **IPP / IPPS** (`ipp://printer/ipp/print`) — the PDF is sent as is, with copies, duplex and optionally the media as job attributes; the printer reports its state, its model and whether it accepts PDF.
  - **Raw port 9100** — the data streamed to the printer, wrapped in PJL for copies and duplex (can be switched off); state from `@PJL INFO STATUS` when the printer answers it.
  - **Windows printer** — any installed or shared queue, chosen from a list; the data is spooled as RAW, status from the spooler.

  **Printers without a PDF interpreter get PostScript**: an office MFP that only knows PostScript and PCL can reset when it is sent a PDF. The data format is *automatic* by default: before sending, imPRESS asks the printer what it understands — IPP on the same host (read-only), else PJL `INFO CONFIG` — and sends PDF when it can, otherwise PostScript Level 3 with every page rendered by PDFium (the preview's renderer; no Ghostscript), in greyscale for a mono printer, 300 dpi by default. A printer that takes neither PDF nor PostScript is refused with a clear message instead of being sent data it would choke on; the last answer is remembered, so a printer whose web service stalls is not suddenly sent PDF. Per target the format can be forced (PDF / PostScript), with resolution and greyscale.
  **Duplex "automatic"** prints two-sided when the job asks for it *or* when the imposition produced fronts and backs (a sheetwise duplex template, such as the business-card presets). The turn follows the imposition (backs are mirrored left-to-right, i.e. head-to-head): long edge of the paper for a portrait sheet, short edge for a landscape one.
  Nothing is rendered by a Windows driver: a Windows queue cannot say what the device understands, so there "automatic" means PDF — choose PostScript for a printer without PDF. Copies (1–999) and duplex (as in the job, one-sided, long or short edge) are set per target, and **Test** shows the printer's state.
- **Send / print by hand**: the Workflow panel (after a confirmation that names the printer and the number of copies) and the portal send a job's newest finished PDF (the PDF/X one if made) to any enabled target — "print this on the Konica now", or a reprint. The job's status does not change; the delivery is logged in its history with the operator's name.

#### Web portal
- **Web portal** at `http://server:port/` — no client to install, Polish and English, light and dark mode, phone layout. A sign-in page, a job list with search and status filters (with counts), job details with a step bar (received → preflight → approval → production → ready → completed), preflight results as a summary plus a checklist ("✓ Fonts embedded", "⚠ RGB images", "✗ Missing bleed"), page previews, output files to download and a history timeline. A New Job form in three sections with drag-and-drop upload, upload progress and an immediate "Job #… received · File uploaded · Preflight: processing" receipt. The portal is compiled into the application — one stylesheet and one script, nothing loaded from the Internet.
- **Live status in the browser**: status changes and progress arrive as they happen (Server-Sent Events); if a proxy blocks the stream the portal falls back to refreshing every 10 seconds.
- **Template, paper and grammage on the New Job form**:
  - **Template**: the print shop's saved templates (including ones created in the template manager) and the application's built-in presets, in two groups, plus "chosen by the print shop". Production uses the job's template unless a rule picks a preset; with no choice the workflow's template applies. The choice is validated against the catalogue (names only — a path is refused), shown in the job details on the web and the desktop, and available over the API (`templateFileName` on jobs, `GET /api/templates`). Built-in presets are addressed by their stable id (`preset-a4-saddle.json`); a saved file of that name takes a preset over. Free-text finishing is still accepted over the API and shown when set.
  - **Paper type and grammage**: the print shop's papers plus stocks already added, and the grammage (60–400 g/m² or any other value). "Add your own type" creates a stock on the spot (name + kind of paper) in the shop's paper catalogue (`papers.json` next to the templates), which the application reads too — it appears in Settings → Workflow Server → Papers at once, marked "web portal" with who added it and when, and the template editor offers the same stocks for creep compensation. A stock may carry the grammages it comes in (one, several or none); the portal lists a paper's own grammages first and preselects the only one, and production and the template editor take a single grammage from the paper itself. For saddle-stitched work with creep compensation the job's grammage and paper kind set the paper caliper.
- **Production board** (`#/board`, "Production" in the menu for staff; a List | Board switch on All Jobs): the shop's work from any computer on the network, one column per stage — Received → Preflight → To approve → Production → Ready → Completed, plus **Needs attention** (on hold, failed, rejected). Headline numbers on top (in progress, to approve, in production, ready, needs attention, overdue, due today — each a filter), the stages as a production line with their counts (a click shows only that stage), search and filters by workflow and priority. Each card shows number, name, customer, quantity, paper, priority (urgent and high are marked), due date (overdue and today stand out), status, preflight verdict, workflow, the hold or error reason and a live progress bar while it is produced; columns are in working order — urgent first, then the nearest due date, then the oldest job.
  - **Actions on the card** are exactly the ones this person may use on this job right now — the server decides, with the same rules the services enforce — so an operator approves and produces, a production manager also releases, a DTP account never sees Approve.
  - **Bulk actions**: select jobs (or a whole column) and approve, produce, complete, retry, release, re-run preflight, hold or reject them at once, or set their priority; every job goes through the service on its own and the result lists any that failed, with the reason. Everything updates live.
- **Managing a job from the web**: staff see the job's way through its own workflow (Input, Preflight, Rules, Repairs, Approval, Imposition, Export, Output, Notify, Complete — done, running, on hold, failed, with details such as "1 error / 3 warnings" or the matched rule) and the actions the server allows: approve, produce, complete, retry, release, preflight again, hold, reject. Accounts that manage jobs change the **priority** in place and **edit the order** — name, customer, quantity, pages, priority, due date, template, workflow, paper, grammage, duplex, notes — without losing what the form does not show. A priority change is recorded in the job's history ("Priority changed", staff only). On a finished job **Send / print** sends it to any enabled target (with the printer's state next to the choice); on a waiting, held or failed job **Auto-repair** lists the repairs that would change something and the problems only the customer can fix, and runs the chosen ones. The shop's job list shows every printer's state in a strip above the table.
- **Administration**: an Administration page, so the shop can be configured from any computer on the network instead of from the machine with the application. Each tab appears only for accounts allowed to use it:
  - **Users** (administrators): create accounts (the generated password is shown once, with a copy button), edit name, e-mail, role and customer, disable or re-enable, reset a password, issue and revoke API keys (the key is shown once).
  - **Outputs & printers** (administrators): add, edit, disable, test and remove folder targets and printers (IPP/IPPS, raw port 9100, a Windows queue picked from the printers installed on the server), with copies, duplex, data format, raster resolution and greyscale; printers report their state as soon as the page opens, and a target still used by a workflow or rule cannot be removed.
  - **Papers** (production managers): add stocks, change their kind and grammages, delete them; built-in papers are read-only.
  - **Workflow** (production managers): the whole recipe — mode, template, output target, description, preflight profile, hold on errors, strict mode, automatic repairs, PDF/X standard, export engine, cutting guide, webhook address and the statuses that trigger it; workflows can be added and deleted. The pipeline is drawn as ten colour-coded boxes like the desktop editor — each saying what it will do with the settings below ("Preflight starts when the file arrives", "PDF/X4 · Automatic", the target's name…), with switches for the optional steps, side exits ("errors → Hold"), the number of this workflow's jobs at each box right now, and the validator's notes (✗ / ⚠ / ℹ on the box and a clickable list under it), re-checked as you edit, before saving. Clicking a box takes you to its settings.
  - **Rules** (production managers): the processing-rule forms.
  - **Server** (administrators): status tiles (state, how the server runs — application, Windows service or console — address, uptime, workers, queue, jobs in progress, connections) and jobs by status, plus the settings: address, port, LAN only, sign-in, session lifetime, workers, stage timeout, upload limit, retention and job folder. Changes that need a restart say so. Switching the server off, HTTPS and access from outside the LAN stay in the application — a browser could lock itself out.

#### In the application
- **Workflow panel**: the Workflow button at the right end of the toolbar (or Ctrl+Shift+W) rolls the job panel down over the editor and back up on a second click; opening a job in the editor rolls it up by itself. Fully in Polish and English.
  - **The queue**: a table of every job with search and filters (status, priority, user, customer, creation date, archive), coloured status labels, a mark on high and urgent jobs and overdue dates in red — or, with the **Table | Board** switch, a board with a column per stage and job cards (priority edge, due date, status, preflight verdict, hold or error reason) in working order.
  - **Production flow**: a strip above the queue with the seven stages and their counts; a click shows only that stage. An **overdue / due today** switch narrows the queue to urgent due dates. The stages follow the same rules as the portal's board, so both show the same.
  - **Job details**: the job's pipeline as a vertical list of steps with their state and details, parameters, the preflight checklist and full report, the timeline, the matched rule and, for a failed job, the failed stage, the reason, the time and a Retry button. A **priority** box (audited, reorders every board, the portal's too).
  - **Actions** grouped into Production (Open in imPRESS, Preflight, Auto-repair, Produce), Decision (Approve, Release, Hold, Reject, Complete, Archive) and Send / print. **Open in imPRESS** opens a working copy of the artwork in the editor; saving or exporting registers the result with the job. **Auto-repair** checks the job's file, lists the repairs that would change something and the problems no repair can fix (such as missing bleed), and runs the chosen ones on a working copy with a fresh preflight.
  - A status bar shows the server and every printer with a coloured dot (printers are checked every 30 seconds while the panel is open), with the server's Start, Stop and Restart buttons.
- **Settings → Workflow Server…** — one window, five tabs:
  - **Server**: enable, address, port, LAN only, job folder, upload limit, start with imPRESS Studio, sign-in, retention, workers and stage timeout — grouped into Server and access, Jobs and files, Processing and Security, with explanations under the fields — plus the Windows service.
  - **Users**: create accounts, edit name, e-mail, role and customer, enable or disable, reset the password, issue and revoke API keys. Passwords and keys are generated and shown once. The last active Administrator can be neither disabled nor demoted.
  - **Output targets**: folders (with a folder picker) and printers (IPP, raw 9100, a Windows queue from the installed printers), with the fields each kind needs and copies and duplex for printers; change, disable, **test** (a folder is written to, a printer reports its state, model and reasons), and see which workflows and rules use a target — one in use cannot be removed.
  - **Pipeline**: the visual editor of workflows. The ten steps are drawn as colour-coded cards joined by arrows, wrapping over rows, with side exits ("errors → Hold", "waits for the operator"); each describes what it will do with the current settings, optional steps switch on and off on the card, and clicking a card opens its settings (the workflow's mode lives on the Approval card). **Checks as you edit** flag what will not work as it looks (Output switched on with a disabled target, Automatic mode with no rules, no template, a Notification without an address…) on the card and in a clickable list of notes. **Live counts** show how many of the workflow's jobs sit at each step, and a card with jobs lists them, most urgent first. **Dry run**: pick a PDF and see what each step would do with it — preflight result, matched rule, repairs that would apply, the approval route, template and sheet, export, whether the output target is reachable — with the pipeline as it stands in the editor, unsaved edits included; no job is created, nothing is written or sent. Processing rules can be switched on and off from the Condition card. Saved through the same validation as the portal and the command line.
  - **Papers**: the paper catalogue shared with the portal — add and remove stocks and set the grammages each comes in.
- **Windows service**: the Workflow server can run as the Windows service "imPRESS Studio Workflow" — the portal, the API and background processing stay up with nobody logged in and come back after a reboot (automatic start, restart on failure). Install, start, stop, restart and remove it from Settings → Workflow Server → Server → Windows service (one UAC prompt per action) or from the command line. The service works on the same database, job folders, templates and paper catalogue as the application, even under another account: both data locations are written into the service's command line (`--data-dir`, `--local-dir`). While the service is installed the application does not start a server of its own (the port belongs to the service); its Workflow panel shows the service's state and its Start/Stop buttons drive the service, and work started on the desktop (preflight after an upload, production) is handed to the service through the database (picked up within about two seconds). Removing the service brings the application's own server back.

#### Integration
- **REST API** under `/api`: `auth/login`, `auth/logout`, `users/me`, `server/status`, `health`, an event stream (`events`), and for jobs: list, create, edit, `status`, `history`, `events`, `timeline`, `pipeline`, `upload` (raw PDF or multipart form), file download, `preflight`, `process`, `approve`, `hold`, `reject`, `release`, `complete`, `retry`, `priority`, `send`, `repairs`/`repair` and `bulk` (one command on many jobs). Everything the portal does goes through the same API, including the production board and administration; API keys (`imp_…`) serve integrations. Full list in `docs/workflow-1.7.0.md`.
- **Accounts and roles**: Administrator, ProductionManager, Operator, DTP and SubmitUser, each an authorization policy. A submitter sees only their own jobs and files work under their own customer name; someone else's job answers "not found".
- **Audit log**: JobCreated, FileUploaded, PreflightStarted, PreflightCompleted, ProcessingStarted, ProcessingCompleted, Approved, Rejected, Hold, Error and Completed, plus repairs, thumbnails, releases, deliveries, notifications and priority changes — each with time, user, job and details.
- **Retention**: Completed and Rejected jobs can be deleted automatically after a number of days (off by default).
- **Command line**: `workflow status | enable | disable | serve`, `workflow user add | password` (a generated password printed once, optionally an API key), `workflow output add | printer | list | test | printers | remove`, `workflow service install [--start] [--account DOMAIN\user --password …] [--manual] | uninstall | start | stop | restart | status`.

### Security
- Submitters never see internal detail: rule names, failure stages and technical error text, staff names and raw event logs stay with the print shop; a submitter sees a neutral message and a restricted timeline, and every staff-only endpoint (board, job pipeline, bulk actions, priorities, pipeline counters) answers 403. The portal runs under a strict Content Security Policy and never inserts markup built from data.
- Designed for a LAN: when enabled the server listens on all interfaces but, in the default LAN-only mode, closes connections from public addresses before any HTTP is exchanged. Serving beyond the LAN needs `--allow-public` together with HTTPS (certificate from the Windows store) or explicit consent to plain HTTP. Login may be switched off only on a 127.0.0.1 listener.
- Passwords are PBKDF2-SHA256 with 600 000 iterations; tokens carry 256 bits of randomness and only their SHA-256 is stored. Login is rate-limited per address and an account is locked for 15 minutes after five failures. Changing a password ends every session.
- Every endpoint declares the permission it needs and the services check it again. Output target settings (folders, printer addresses) are shown on the web only to accounts with the ManageServer permission (administrators); operators see names and printer states. A bulk request is refused as a whole (403) when the caller may not use its action at all, holds at most 200 jobs, and each job is then checked again by the service. The administration API goes through the same services, validation and audit as the application and the command line.
- Uploads: allowed types only, size limit enforced while streaming, `%PDF-` signature and a full parse by the existing analyser. The client's file name is display-only — files are stored under generated names, never overwrite anything, and every path is checked to stay inside its job folder. No static files, no directory listing, downloads always as attachments, no stack traces in responses. Production re-checks the licence for every job.

### Changed
- **Never stuck, never silent**: every failure moves a job to Error with its stage (upload, preflight, imposition, export, output), a short reason and the time; Retry resumes from that stage. A stage running longer than the configured limit (30 minutes by default) is stopped and reported, and an upload interrupted by a restart returns the job to New.
- One definition of the template file format (`TemplateSerializer`) and of the per-job preflight profile (`PreflightProfileFactory`) replaces identical copies in the CLI, hot folders, main window, template editor, preset materialiser and numbering migration. Files and verdicts are unchanged.
- The command-line `impose` verb runs through the new shared production service, the same path the workflow uses.
- PDFium rasterisation moved out of the preview renderer into a UI-independent `PdfRasterizer`, shared by the preview and the server's thumbnails. The preview renders exactly as before.

### Migration
- **Nothing changes for an existing installation until the Workflow server is switched on.** Templates, hot folders, the CLI and exports work as in 1.6.5. The workflow database (`workflow.db`, schema v6) and the job folders are created when the server is first enabled; a database written by a pre-release 1.7.0 build is migrated automatically.



## [1.6.5] - 2026-09-22

### Changed
- **Sheet numbering moved out of the export options and into the template**, under Templates → Extras, next to the logo overlay and ticket numbering. It is a property of the product, not of the person exporting it: the same job now carries the same numbering whether it is exported from the main window, a hot folder or the CLI, and a template can be handed to a colleague with its numbering intact. The export dialog's checkbox, its position dropdown and its format field are gone.
- **The number's format uses the same named tokens as the slug line** — `{sheet}`, `{sheets}`, `{side}`, `{filename}`, `{template}`, `{jobid}`, `{date[:format]}` — instead of the positional `{0}` / `{1}`. One convention for one concept, and the number can now carry the file name or the job id alongside the count.
- **The preview draws the number as permanent chrome rather than a badge that fades after two seconds.** It is part of the sheet's design now, so it is shown the way the slug line is, in the place the export will stamp it, on both sides. The template editor's sheet thumbnail draws it too, planned by the same helper the composer uses, so the thumbnail cannot promise a placement the export will not honour.

### Added
- **Page numbering — the source PDF's page number stamped inside each item**, under Templates → Extras. The folio of the finished product: on an imposed notebook or calendar every item carries the page it actually is, so a proof can be checked against the original document and a mis-ordered signature shows up on the sheet. Fronts and backs, blank slots skipped, format built from `{page}` and `{pages}`, with a start number for documents whose page 1 is not the product's page 1. The preview stamps it in the same place the export does.
- The Extras tab now holds three numberings, which are easy to confuse, so each says what it counts: **page numbering** repeats the source page of the item, **ticket numbering** runs a counter of its own across the products and ignores what is printed on them, and **sheet numbering** counts press sheets and shares one number between a sheet's front and back.
- **Start number and step for sheet numbering.** A reprint can continue an earlier run ("this batch starts at 240") and a countdown is a negative step. Overflow is clamped rather than wrapped, because a silently negative sheet number on press is worse than a stuck one.
- **Per-side selection**: number both sides, fronts only or backs only — front and back of one sheet still share a number, since the number identifies the sheet and not the side. Use `{side}` to tell them apart.
- **Mirror on back**, which places the number on the same physical corner of the sheet once the stack is turned, instead of the same corner of the page image.
- **Anchoring to the usable area** instead of the physical sheet edge. On a large sheet a 5 mm inset lands in the gripper and never prints; anchored to the usable area the number follows the sheet margin. A margin wide enough to collapse the usable area falls back to the whole sheet rather than placing the number off-sheet.
- **Nine anchor positions** (the same set the logo overlay and ticket numbering use) instead of six, separate X and Y offsets instead of one shared inset, and a registration-black option for offset forms.
- **A non-blocking advisory in the template editor** when the marks profile's slug line also prints `{sheet}`, which would stamp the number twice. It is flagged rather than rejected — a slug along an edge and a number in a corner is a legitimate layout — and it never stops a save.
- Help gained a "Template extras" section covering the logo overlay, ticket numbering and sheet numbering, and explaining where sheet numbering went.

### Fixed
- **Ticking a section's “enabled” box in the template editor now ungreys its fields immediately.** Contour-cutter marks, creep compensation and ticket numbering gated their inputs on a binding that read the template object directly; the template is a plain data object with no change notification, so the box was ticked, the value was stored and the fields stayed greyed out until the dialog was closed and reopened. All the optional sections now go through the same notifying wrapper the logo overlay already used, and a headless-UI test ticks every one of them through the real dialog.
- **Switching tabs in the template editor scrolls back to the top.** All four tabs share one scroll area and only swap which panel is visible, so the offset survived the switch: arriving from a long tab landed the operator in the middle of the next one, with its first card above the viewport. With Extras now holding four cards, that was enough to make a section look absent.
- **The sheet number landed in the wrong place at any zoom other than 100%.** The preview measured the sheet in screen pixels and handed it to the placement helper, which converts its millimetre insets to PDF points — at 1:1 the two coincide and it looked correct, everywhere else the number drifted, and with usable-area anchoring and a wide sheet margin it could be pushed far enough to read as missing. Placement now goes through one scaled entry point that cannot mix the two units, and the same mistake in the template editor's thumbnail is gone with it.
- **A spread's back pane no longer shows a sheet number when the plan carries no verso.** The composer writes a back page only when there are back placements; the preview stamped one regardless, promising a numbered side that never reaches the file.
- **The preview expands `{jobid}` instead of leaving it empty.** It was hardcoded blank, so the slug line, the tracking barcode and the sheet number all rendered shorter on screen than in the exported file — and a format built from nothing else rendered as nothing at all.

- **A reprint no longer reuses ticket numbers that are already out in the world.** Exporting a sheet range cut the plan down to the selection before composing, so everything counted across the run counted the reprint instead: the ticket sequence restarted at 1, and a reprint of sheets 3–5 out of 39 handed out the same numbers as the original press run. A sheet range is now an output selection, not a smaller job — the whole plan reaches the composer, unwritten sheets still advance the counter, and a reprinted sheet comes out identical to its page in the full run.
- **The sheet total in the marks is the planned total again, not the size of the reprint.** The same truncation made the slug line, the sheet-number stamp and the tracking barcode read "sheet 3 of 3" on a three-sheet reprint of a thirty-nine-sheet job. The cutting guide, which describes the file rather than the run, still covers only the sheets actually written.
- **Blocking an export on an invalid licence says why.** The status bar showed the literal text `St.ExportBlockedNoLicense` — the key had no entry in either language, and the indexer returns the key it cannot find — while the actual reason was passed to a format string with nowhere to put it and silently dropped. The message now exists in both languages and carries the validator's explanation. Three new tests pin the whole surface: both dictionaries defining the same keys, every key the application asks for existing, and every formatted string having somewhere to put its argument.
- **Contour-cutter (OPOS) markers have their own preview toggle.** They were drawn behind the crop-marks filter, so unticking crop marks to inspect a sheet hid markers the exported file was still going to carry — the preview asserting the opposite of what shipped. They now sit beside the other per-type filters, greyed out when the marks profile defines no markers, and the crop toggle again governs crop marks alone.

- **The logo overlay is now visible in the preview and in the template thumbnail.** It had always reached the exported PDF, but nothing ever drew it on screen, so switching it on changed nothing anywhere in the application and the feature looked broken. Both previews now place it with the same helper the composer uses, so what is lined up on screen is what gets stamped. Raster logos are drawn; a PDF logo rasterises through the same background renderer as page content and shows its footprint until it lands. A missing or undecodable file draws the footprint outline instead of taking the editor down.
- **A template edit now discards the cached preview bitmap instead of re-blitting it.** The preview composes a whole sheet into one cached image; changing the template asked for a repaint but not for the cache to be dropped, so marks, overlays and numbering could keep showing the previous template's state until something unrelated forced a rebuild.
- **The contour-cutter box and the marks-profile dropdown follow a newly loaded template.** Applying a preset or loading a template from disk replaces the whole template at once; these two controls were not told, so they kept showing the previous template's state over the new one's data — the profile dropdown in particular named a profile the template no longer referenced.

### Migration
- **The old export-side setting is written into the saved templates on first start**, into every template that does not already define its own sheet numbering, and the status bar reports how many were touched. Before the move the checkbox applied to every export regardless of template, so leaving the setting behind would have silently dropped the numbers from work that has always carried them. ## [1.6.3] - 2026-09-09

### Added
- **The preview shows the job in the colours the press can actually reproduce.** When an ICC output profile is selected in the export settings, pressing Plan now renders the sheet through that profile — the same one export embeds as the output intent — instead of in screen RGB.

  It is a real ICC transform through the Windows colour system, not an approximation: sRGB into the chosen CMYK space and back out to sRGB, relative colorimetric on both legs. What that leaves on screen is exactly the difference the press will introduce. Saturated greens and blues that no ink set can hold collapse toward what it can; everything already inside the gamut is left where it was. Until now the operator laid out a sheet in bright RGB and first met that difference after exporting, or when the proof came back.

  The strip along the bottom of the preview gains a **PROOF** badge naming the profile in force, because an operator who cannot see why the greens went dull will read it as a rendering fault. Clearing the profile in the export options turns it off. The channel view and the overprint simulation now sit on top of the proofed colours rather than beside them — they are ways of looking at the sheet that will be printed.

  A profile the colour system cannot open leaves the preview working in plain screen colour rather than failing; the export path still reports it properly when it comes to use it. The proof is Windows-only, like the rest of the colour path, and where it is unavailable the preview behaves as it did before.

### Fixed
- **Installing over a machine running the hot folder service failed with "DeleteFile; code 5. Access denied".** The service runs the installed executable, so while it is running it holds every DLL in the program directory open, and Setup stopped at the first one it tried to replace — naming `Avalonia.Base.dll` and saying nothing about why.

  `CloseApplications` did not cover it. The Restart Manager closes applications; a service running as LocalSystem is neither closed by it nor stoppable by a Setup that runs, correctly, without elevation. So the installer never learned about the service the application had been able to install since 1.6.0, and every update on a shop that uses service mode would have hit this — including the silent in-app update, where it would have failed with no visible reason at all.

  Setup now stops the service before copying files and starts it again afterwards, through elevated `sc.exe` calls, which is where the UAC prompts during an update come from; they appear only on machines that actually run the service. If the stop does not go through, the installation aborts with a sentence saying what to do instead of a file name and an error number.

- **Uninstalling left the hot folder service registered**, pointing at an executable that no longer existed — it failed at every boot and could only be removed with `sc.exe`. The uninstaller now stops and removes it.

### Changed
- **The application is precompiled to native code at publish time, and starts about twice as fast.** Prompted by reports of slow startup on older machines, and by telemetry showing 45 seconds on one of them against under two on a current desktop.

  The cause was that everything which is not Microsoft's own framework shipped as IL: our own assembly, the whole of Avalonia and the PDF stack — 166 files and 28 MB — recompiled by the JIT on every single cold start. The framework assemblies were already precompiled, because that is how Microsoft ships them, which is exactly why the cost was close to invisible in profiling here and brutal on an old machine: JIT work is CPU-bound and scales directly with single-thread performance. Running with `DOTNET_TieredCompilation=0` put a number on it — pure compilation accounted for roughly 800 ms of a 950 ms start on a modern desktop.

  Measured on the same machine, comparing published builds of identical code:

  | | first run (cold) | subsequent (median) |
  |---|---|---|
  | before | 2730 ms | 952 ms |
  | after | 1421 ms | 570 ms |

  Machines that are slower per core stand to gain proportionally more, because the part that disappears is precisely the part that scaled with them.

  The cost is size: the installer grows from 41.5 MB to 50.7 MB, and a release build takes about twenty seconds longer. Composite mode was measured too and rejected — it is faster once warm (488 ms) but takes 5406 ms on a cold start, because one large image has to be paged in before anything runs, and a cold start on a slow disk is the case this was meant to fix.

  Nothing about the application changed; this is how it is compiled. `dotnet build` and the test run are untouched, and the setting is conditioned on a runtime identifier so a plain `dotnet publish` still works.

## [1.6.0] - 2026-09-05

Preflight grows the checks a prepress department expects to find and misses when they are absent, gains two repairs for the failures that stop a file at someone else's gate, and both preflight windows are rebuilt around the decision they exist to support. Along the way, two things an operator simply could not reach: the report writer that shipped in 1.5.12 with nothing calling it, and a template manager that never showed the template the job was running.

### Added
- **Ten checks, every one of them reading something the analyzer had been extracting all along.** Page rotation, encryption, PDF version against the target standard, the PDF/X title and XMP requirements, line-art resolution and the separation rules were all measurable from data already in the report — nothing was looking at it. That is a particular kind of gap: no failure, no log line, just a rule that was never written.
  - **Page rotation** (`PAGE_ROTATION_SET`, `PAGE_ROTATION_MIXED`). Rotation in PDF is a viewing instruction, not geometry: the boxes keep the numbers they were written with and the reader turns the result. Consumers all honour it and disagree about what it means for the boxes, so a 90° page whose TrimBox reads 210×297 imposes as a portrait item and prints on its side — and the operator has no reason to suspect it, because the screen shows the rotated page. Mixed rotations are reported separately and as an error: one rotation throughout can at least be compensated, a document where some pages turn and others do not cannot be imposed correctly under any single reading. The angle is normalised first, because `/Rotate` is defined modulo 360 and a file may legally say 450 where it means 90.
  - **Encryption and empty documents** (`PDF_ENCRYPTED`, `PDF_NO_PAGES`). A file carrying permission flags opens perfectly in a viewer and then refuses to be placed, imposed or ripped. Reporting it at preflight turns a late, cryptic export failure into a fact the operator can act on while the customer is still reachable. An empty document stops the rest of the checks rather than producing a page of findings derived from nothing.
  - **PDF version against the target** (`PDF_VERSION_ABOVE_TARGET`). Each PDF/X flavour is defined on a specific version — X-1a and X-3 on 1.4, X-4 on 1.6 — and a file above it carries constructs the standard cannot describe.
  - **The two PDF/X metadata requirements** (`DOC_TITLE_MISSING`, `XMP_MISSING`). The cheapest possible conformance failure: nothing about the artwork is wrong, the file simply does not say what it is, and a validator downstream rejects it while the pages look perfect. Reported only when a PDF/X target is actually selected — outside that it is tidiness, and preflight that reports tidiness as loudly as defects teaches operators to stop reading it.
  - **Line-art resolution** (`IMAGE_LINEART_DPI_LOW`), with a threshold of its own. A 1-bit image has two values and nothing in between, so every edge is built from whole pixels: 300 dpi hides its sampling in a photograph and puts visible stair-stepping on every diagonal of a scanned signature or a die-line. The industry figure is around four times the contone one, which is why measuring both against a single threshold reports the wrong thing twice. `ImageDpiValidator` now skips 1-bit images entirely, so one low-resolution bitmap produces one finding with the right number in it rather than two that disagree.
  - **The `All` colorant** (`SPOT_ALL_COLORANT`). A Separation named `All` is defined by PDF 1.7 §8.6.6.4 to paint on every plate at once. It exists for registration marks and arrives in customer artwork by accident — a mark copied off a template, a swatch picked from the wrong end of the panel. Nothing about it looks unusual on screen, and on press it inks the object into all four process plates plus every spot. Matched exactly: a spot genuinely called "Allura Red" is a colour, and an error on a correct file costs more trust than the check earns.
  - **Plate count against the press** (`SPOT_COUNT_OVER_LIMIT`). How many spot colours a job may carry is a property of the machine, not of the file: nine are perfectly legal PDF and simply unrunnable on a six-unit press. Counted on distinct colorants, because the same ink named on three pages is still one unit, and the `All` colorant is excluded — it is a defect to remove, not an ink to plan for.
- **Two new repairs.** Both change document-level declarations rather than marks on the page, which is what makes them safe to offer and worth offering: a file can be perfect artwork and still be rejected because of what it fails to say.
  - **Document metadata** writes the title (from the file name) and the `/Trapped` declaration ISO 15930 requires — `/Unknown` and its absence are both non-conformant. **The trapped key is asserted, not guessed**: `/False` is a statement a RIP acts on, so the repair declines the moment the report shows a trap network in the file. Telling a trapped file it is untrapped is how work gets trapped twice, and double-trapping is a press problem rather than a validation one.
  - **Layer print state** stops layers hidden on screen from printing. Optional content carries two independent states — visible, and printing — and design files routinely end up with them disagreeing, because hiding a layer does not touch a print setting that defaults to on. The operator sees clean artwork and the plate comes back with the die-line on it. Nothing is deleted: the content stays and the layer can be turned back on, which is what separates this from flattening. Visible layers are never touched — a layer you can see is a layer you have decided about.
- **Hot folders accept CIP4 job tickets — JDF 1.x and XJDF 2.x.** A shop's MIS already describes every job it schedules: finished size, press sheet, binding, sidedness, and which file to print. Until now that description stopped at the hot folder and an operator retyped it into a template, or accepted whatever the folder's fixed template happened to say. A folder with tickets enabled reads the ticket instead, and imposes the PDF the ticket names.
  - **The ticket describes the work; it is not the work.** Dropping a `.jdf` in does not impose the ticket — it resolves the artwork the ticket points at, imposes that, and files the two together afterwards. Artwork first, ticket last is the convention every MIS follows, and the folder waits for the artwork anyway when they arrive the other way round.
  - **The folder's template is the floor, the ticket is the override.** A hot folder carries a shop's settled decisions about marks, bleed, gutters, sheet margins and creep. A ticket states a handful of things about one product, so those are what it changes — finished size, press sheet, binding, one- or two-sided — and everything else is left alone. Building a template from the ticket instead would throw away every decision the operator made. Each override is written to the job log with the value before and after, because a sheet that came out 700 mm wide has to be traceable to the ticket that asked for it.
  - **Both generations, and both ways 1.x states a value.** JDF 1.x wraps intent values in span sub-elements carrying `Actual` and `Preferred` — the negotiated value and the requested one, with `Actual` winning — while plenty of writers put the value straight on the intent element instead. Files a print shop actually receives contain both, so both are read. XJDF 2.0's flattened form is read the same way.
  - **Points, not millimetres.** CIP4 states every measurement in points of 1/72 inch. A ticket saying 595.276 means A4 width, and the conversion happens in the reader so nothing downstream can forget it. Numbers are parsed invariantly, which is the difference between a feature that works and one that reads 595.276 as 595276 on a machine set to Polish.
  - **A binding this application cannot impose is named, not approximated.** CIP4 has a dozen bindings — ring, tape, sewn, hard cover — and mapping them to the nearest neighbour would impose ring binding as saddle stitch. Unmapped bindings leave the template's own binding in place and put the ticket's word in the log.
  - **The page count is never taken from the ticket.** The count that governs imposition is the one the PDF has; a ticket that disagrees is reported and not believed.
- **Job tickets are treated as the hostile input they are.** A hot folder accepts files from whoever can write to a watched directory, and an XML job ticket is the one format in this application that an outsider both authors and expects to be parsed. So DTDs are prohibited outright and no resolver is supplied, which closes external-entity reads (`file:///C:/…`, or a connection opened from inside the print shop's network) and entity-expansion denial of service in one move; document size and length are capped as well. Artwork references are resolved, normalised and only then checked to fall inside a directory the operator allowed — in that order, because normalising after checking is how traversal defences are defeated. Absolute paths are allowed inside a root, so the normal MIS installation works, and `http`, `https` and `ftp` references are refused outright.
- **Hot folders can run as a Windows service.** A hot folder is production infrastructure — the shop expects files dropped at 04:00 to be imposed at 04:00 — and run from the desktop application it stopped the moment the operator logged off, with a workstation that rebooted overnight coming back watching nothing until somebody noticed. `hotfolder service install / start / stop / uninstall / status` registers and drives it, and the hot folder manager offers the same four actions with a status line, elevating through UAC because the application otherwise runs without administrator rights and should keep doing so.
  - **The service is told where the operator's data lives.** Configuration, the licence and saved templates sit in the roaming profile of whoever set the folders up, and a service does not run as that person: as LocalSystem its `%APPDATA%` is under `C:\Windows\System32\config`, where it would find an empty configuration, no licence, and quietly watch nothing — the failure with no symptom. The installer captures the path and passes it as `--data-dir`, which is parsed before anything else so that the whole process resolves one set of roots rather than two.
  - **A named service account is offered**, because LocalSystem authenticates as the machine and a file server routinely refuses it — which is most shops, whose hot folders sit on a share.
  - **Restart on failure is configured at install time**: three attempts a minute apart, reset daily. The point of a service is that a folder which dies at 02:00 on a network hiccup does not stay dead until 08:00.
  - **The service control handshake is treated as the real constraint it is.** The SCM allows a few seconds to acknowledge a start before declaring the service hung, and starting the host is I/O — configuration, the ledger database, staging directories, a scan of input folders that may be on a slow share. So the start is acknowledged immediately and performed on a background thread, and a start that fails stops the service with a non-zero exit code rather than sitting in "running" while watching nothing.
- **The hot folder template list offers the built-in starting points, not only saved files.** On a fresh installation the list was empty, so configuring the first hot folder meant opening the template manager, building a booklet and saving it before coming back. Picking a preset now writes it into the ordinary templates directory and points the folder at it — from that moment it is a template like any other, visible in the template manager and editable, because a preset the operator cannot adjust is worse than no preset. An existing file of the same name is left alone: replacing a template somebody has since tuned, because they picked the same preset twice, would be silent and destructive.
- **Two more thresholds in the press profile**, following the same rule as the rest: line-art resolution and the spot-colour limit describe the machine, so they belong to the profile rather than the job. Offset carries a 1200 dpi line-art floor and a two-plate spot limit, newsprint 800 dpi and one, digital and large format no plate limit at all — they separate to process or run from a roll, where the count is not the constraint.

### Changed
- **The export preflight window was rebuilt around the decision it exists to support.** It stated its findings in a sentence — the one thing an operator with a customer waiting does not read — and rendered them as a flat list in colours hard-coded in hex, which made it the one window in the application that stayed the same shade whatever theme was chosen. Now the verdict is the headline, the counts are chips beside it (and a severity with nothing in it gets no chip, because "0 errors" next to "3 warnings" makes you read two numbers to learn one thing), the findings are grouped severest-first under headings that say what each severity means for the export, and every colour comes from the theme's semantic brushes. A severity filter appears once there is enough to narrow — a forty-finding report is read by asking "what is blocking me" first — and a severity nothing was found for cannot be selected, so no click lands on an empty list. The findings can also be copied to the clipboard: relaying one to whoever made the file previously meant retyping it out of a modal dialog.
- **The validation tab in File info gained the same filter**, plus a count on every category heading, so the shape of a long report is visible without counting rows. The "what to fix first" panel is deliberately still computed from the whole report and never from the filtered subset — it answers a question about the job, and recomputing it inside a filter would quietly answer a different one.

### Fixed
- **Hot folders demanded Ghostscript for work that no longer needs it.** Since 1.5.12 the imPRESS Export Engine packages PDF/X-1a, X-3 and X-4 itself, but the hot folder validator still refused to save any configuration that asked for PDF/X without a path to `gswin64c.exe` — an executable this application does not ship and most machines do not have, because Ghostscript is separately licensed AGPL software. A configured path that points at nothing is still an error; choosing the Ghostscript engine with no path is now a warning, since it may be found on `PATH` at run time. Three user-facing texts that described Ghostscript as bundled with the application were corrected as well, in both languages.
- **Native exports queued behind a limit meant for Ghostscript.** The concurrency throttle exists to stop N simultaneous Ghostscript processes from taking the machine down; it was taken for every PDF/X job regardless of engine, so a folder pinned to the native engine serialised its work behind a limit protecting it from a tool it never invokes. Auto still takes a slot — it decides per file, inside the pipeline, and may yet fall back.
- **Installing the service from the manager did nothing, and the UAC prompt said ".NET Host".** Both the elevation and the service registration took `Environment.ProcessPath` to be the application, which it only is when the application was started through its own apphost. Started as `dotnet "imPRESS Studio.dll"` — what `dotnet run` does, and a plausible way to script a server install — the process is `dotnet.exe`, whose file description is literally ".NET Host". So the operator was asked to elevate the .NET host, and the host was then handed `hotfolder service install`, which it does not understand: it exited immediately, without a window, and the manager reported nothing at all. Registered as a service the same mistake is worse — the service starts, cannot parse its own command line, and stops with nothing anywhere saying why. The launch command is now resolved rather than assumed, naming the managed assembly when the host needs it, and the manager checks the service state afterwards so an operation that achieves nothing says so with its exit code instead of leaving the window unchanged.
- **The service is named for the product rather than for a schema.** The SCM key is `ImpressStudioHotFolders` — plain ASCII, no spaces, capitalised like a type name, because a service key gets typed into consoles and pasted into scripts by people who have never seen the product's stylised lower-case spelling. Services.msc lists it as **imPRESS Studio Hot Folders**: product first so it sorts with anything else this application ever registers, and without a trailing "Service", which the list it appears in already implies.
- **A failed service operation reported nothing at all.** Installing a service needs administrator rights, so the work happens in a second process started through UAC — a separate, console-less instance whose output goes nowhere and whose exit code is a number. An operation refused for a perfectly ordinary reason (the account name is wrong, the service is marked for deletion, group policy forbids it) therefore reached the operator as a window that did not change, which is the least actionable failure a program can produce. The elevated process now writes its result into the operator's own data directory and the manager reads it back and shows it — the file travels downward across the integrity boundary, which is the direction that works, and is deleted as soon as it is read so a stale result can never be reported as this attempt's outcome. When no result was written at all, that is reported too: it means the elevated process never reached the command.
- **Every CLI command reported success even when it failed.** `Environment.ExitCode` set inside a `System.CommandLine` handler is discarded when `Main` returns an int, so `hotfolder service install` exited 0 after refusing to do anything — and any script or caller checking the code was told it had worked. The parser's result and the handler's exit code are now combined, worst wins.
- **Nothing the hot folder manager asked of the service actually ran.** Install, start and remove all produced a UAC prompt and then no change: the service stayed exactly as it was. `--data-dir` decides where every persistent file is read from, so it is parsed by hand in `Program.Main` before the command parser or the composition root exist — and it had never also been *declared* in the command tree. Every command carrying it was therefore rejected as a parse error, and the elevated process printed usage to a console it did not have and exited. From the desktop the failure was invisible; from a console the same command worked, because a console invocation does not pass the option. It is now a global option on the root command, accepted (and ignored) everywhere, while an option the parser genuinely does not know is still rejected. `status` also gained the `--result-file` its four siblings already took: a subcommand that refuses an option the others accept is a button that silently does nothing, which is how this was found.
- **The CLI ran correctly and printed nothing.** Every command invoked from a console produced no output at all — not an error, not a result, nothing — and the operator was left to conclude the program had not run. It had: the log shows each invocation starting and doing its work. A Windows-subsystem executable is given no standard handles by `cmd.exe`, and .NET binds `Console.Out` to whatever `GetStdHandle` returns the first time it is used; once that is an invalid handle, every write goes nowhere for the life of the process. `AttachConsole` gave the process a console to draw on but did not repair those handles, so the half of the fix that had been there since the CLI was written was the half that does not matter on its own. The handles are now opened explicitly against `CONOUT$` / `CONIN$` and installed before the streams are rebound — and a handle the caller already supplied is left alone, so redirection to a file or a pipe still goes where the caller is reading.
- **A service command leaves an audit trail.** Registering a service is an administrative act, and it is also the one operation whose output an operator most often cannot see: an elevated process has no console at all. Every outcome is now written to the application log as well as to the console and the result file.
- **The service layer speaks the operator's language.** Twenty-three messages from the Windows-service commands — the ones that now reach the manager's status row and the CLI — were English regardless of the interface language, in an application that is otherwise bilingual throughout. They are resolved through the same localisation service as everything else. The log line that carries them keeps its English structure, so a support reader still recognises the event even when the message inside it is Polish.
- **The documentation PDFs were four releases out of date.** They were built on 31 August, described 1.5.12, and contained neither the CIP4 job tickets, nor service mode, nor the rewritten preflight chapter — while the HTML beside them, which the site links first, had all three. All four are regenerated from the current sources, and the page count quoted on the download cards now matches what is actually in the file rather than what used to be.
- **The hot folder screenshots showed the wrong window, from the wrong version.** The image captioned "hot folder manager" was in fact the *editor*, captured before 1.5.12 — complete with the "Ghostscript path" field the release removed, on a page that tells the reader PDF/X needs no Ghostscript. The manager now illustrates the manager (including the Windows-service row), the editor has its own figure showing the built-in starting points, and both exist in Polish and English.
- **The template manager did not show the template in use.** `TemplateEditorViewModel` is a singleton, and nothing ever handed it the active template — so every way of choosing one that does not run through that editor (a suggestion applied from the suggestion dialog, the default template auto-loaded at startup, a restored session) left the manager displaying whatever it happened to hold last. An operator who applied a suggested business card and opened the manager to check it was shown a different template, with nothing to say that what they were looking at was not in use. The manager now opens on the active template, seeded at the one place all four routes pass through. It adopts a copy, so editing there still changes nothing until *Use template*, and it leaves the editor alone when it is already showing that setup — otherwise reopening the manager would forget which file the template came from and turn the next *Save* into a *Save as*. The comparison deliberately ignores the template's `Id`: `Validate()` mints one whenever it is missing, so the same setup routinely carries two different identifiers, while a template adapted from another one carries its source's — the identifier answers neither question.
- **The saved preflight report could not be saved.** `PreflightReportWriter` shipped complete in 1.5.12 — eleven passing tests of its own, an entry in the changelog saying a report could be saved — and nothing in the application ever called it. There was no button. Every test supplied its own caller, which is precisely why none of them could see that the product had none: a class with no caller is invisible to a suite that always provides one. *File info → Validation* now carries **Save report**, next to the repairs that act on the same findings, and writes the report as it stands — same findings, same order, same press profile — so what reaches the customer is what the operator was looking at. A test now asks the opposite question of the usual one: does the UI call this at all.
- **Repairs were judged against default thresholds rather than the shop's.** The File info dialog asked the fixup engine what applied using a freshly constructed profile instead of the one the report was produced with, and ran the chosen repairs the same way. A shop whose profile raises RGB to an error, or lowers a resolution floor, got its findings from its own profile and its repairs from someone else's.

### Tests
- 188 new tests. The ones worth naming are about boundaries rather than happy paths: that mixed page rotations suppress the plain rotation finding instead of reporting one problem twice, that `/Rotate 450` and `-270` are recognised as the same 90° before anything is judged, that a spot called "Allura Red" is not the reserved `All` colorant, that the `All` colorant does not consume a press unit, that the metadata repair refuses to declare a trapped file untrapped, and that the layer repair deletes nothing and leaves visible layers alone. Eight cover the manager adopting the active template, two of them on the trap that made the obvious implementation wrong: the same setup routinely carries two different `Id`s (`Validate()` mints one whenever it is missing), while a template adapted from another one carries its source's, so the identifier had to be left out of the comparison entirely. Two ask questions no ordinary unit test can: one pins the call site between two view models that were each correct while the call between them was missing, and one greps the UI sources for references to the report writer and the fixup engine, because the failure it guards against is the ABSENCE of a caller rather than a wrong one. One test was written wrong first and caught by its own teeth check: it asserted that the contone check skips line art using a 300 dpi image, which sits inside the acceptable band anyway, so it passed with the skip removed — the resolution is now below both floors, where the assertion means something. The job-ticket suite is weighted the same way: most of it covers what the reader and the resolver REFUSE, because that is where the value of both components sits. One of those tests was written wrong too — it put the external entity in an attribute value, which XML forbids outright, so it passed with every defence removed and proved nothing. Referenced from element content, where it is well-formed and would resolve, it fails the moment either guard is taken away. The hot folder additions are pinned where they can be: that PDF/X validates without Ghostscript for all three flavours, that `--data-dir` is parsed before the application exists and refuses a trailing option or the next flag as a directory, and that picking a preset twice does not overwrite a template the operator has since edited. Every built-in preset is also fed through template validation, because a preset a hot folder runs unattended should fail here rather than at 04:00. The launch-command resolution is pinned on both branches, which took two attempts: the first version read the process path itself, so under a test runner it only ever exercised the apphost branch and passed with the .NET-host branch deleted. Taking both inputs as parameters is what makes the branch that actually broke reachable.

## [1.5.12] - 2026-08-31

Two bodies of work. Ghostscript stops being a dependency — the imPRESS Export Engine now packages all three PDF/X flavours, so nothing in the product requires an external, separately-licensed tool. And preflight is brought up to professional standard: the report's advice panel had drifted away from the rules it advises on, strict mode refused ordinary booklets, and a shop had no way to say a check does not apply to it.

### Added
- **PDF/X-1a:2001 and PDF/X-3:2003 are packaged natively.** They were the last two features that forced the Ghostscript path. Both are defined on PDF 1.4 and differ from X-4 in exactly three ways, all now handled in one place: the PDF version stamped on the file, the conformance string claimed in the info dictionary and the XMP packet, and the ban on live transparency. Ghostscript remains selectable, but it is an option rather than a requirement — and it is not distributed with the application, being separately licensed AGPL software.
  - **Transparency is handled honestly, not by pretending to flatten.** Turning genuinely non-opaque artwork into opaque marks means compositing the page. That is a rasteriser's job, and doing it would silently convert vector text into pixels — the one thing a prepress operator must never discover after the fact. Instead the engine removes the transparency constructs that are provably *inert*, and refuses — naming what it found — when the file carries transparency that actually paints.
  - **That covers the case which actually occurs.** Most print-ready artwork contains no live transparency at all, yet still fails PDF/X-1a validation, because anything that has passed through Illustrator or InDesign inherits a page-level `/Group << /S /Transparency >>` plus a handful of `/ca 1`, `/BM /Normal`, `/SMask /None` graphics-state entries. Every one of those is a no-op: a transparency group whose members are all fully opaque and composited in Normal mode renders identically to ungrouped content. Dropping them changes no pixel while making the file conformant.
  - **Conservative by construction.** Inert entries are stripped only when the whole document is free of real transparency. A single `/ca 0.5` anywhere means nothing is stripped and the export is refused: an isolated or knockout group becomes observable once real transparency is in play, and quietly dropping it there would change the printed result.
  - **X-1a colour is verified, not assumed.** The standard permits DeviceCMYK, DeviceGray and spot only. Rather than trusting the caller's conversion flags, the engine re-scans the file it has just written and fails the export if any DeviceRGB survived. A wrong flag, or a construct the converter skipped, can no longer yield a file that claims CMYK-only conformance while carrying RGB.
- **A shop can decide what each check is worth — including switching it off.** A profile now carries per-code severity policy (`Off`, `Info`, `Warning`, `Error`) keyed by the stable issue code. A printer who traps in the RIP can silence the trapping advisory; one running a CMYK-only press can raise RGB from warning to error; one who deliberately pads booklets can drop the note entirely. Until now the only per-check control was three hard-coded booleans, so every other rule fired at whatever severity its author chose, for every shop, forever.
  - **Applied in one place.** The policy is enforced in `PrepressValidationContext.Add`, which every validator funnels through, so all twenty rules — and any added later — inherit it without knowing the mechanism exists.
  - **`Off` means gone, not demoted.** A suppressed finding is neither listed nor counted, so it cannot gate a strict export from behind a filter.
  - **A profile from a newer build still loads.** Unknown codes and unparsable policy names are skipped rather than rejected, so a settings file that mentions a check this version does not have degrades to default behaviour instead of failing to open.
- **The report can be saved.** `PreflightReportWriter` renders a result as plain text: header (file, profile, timestamp, verdict), then findings severest-first, repeats of one code collapsed, and consecutive pages folded into ranges — `1-3, 7, 11-13` rather than a line of forty numbers. A prepress finding is an argument with a customer about whose file is wrong, and it wants to travel with evidence; until now the only way to communicate one was to describe it from memory. Plain text on purpose: it opens everywhere, pastes into a mail without becoming an attachment nobody opens, and stays greppable in an archive years later. A message whose arguments do not match its template degrades to the bare code rather than taking the save down.

- **The left setup panel collapses too.** The inspector has had a collapse handle on its seam with the canvas for a while; the setup panel on the other side had none, so on a laptop screen the canvas was stuck with whatever was left of 312 px it could not reclaim. It now carries the mirror-image handle, and the glyph points the way the panel travels (`‹` to collapse, `›` to bring it back) rather than both tabs showing the same arrow. Both side columns are `Auto` with the width on the panel itself, which is what makes hiding one actually hand the space to the canvas instead of leaving a band of empty background where it used to be.
### Fixed
- **Every sheet the composer wrote carried an RGB transparency group.** PdfSharpCore stamps `/Group << /CS /DeviceRGB /S /Transparency >>` onto every page it serialises — measured on a blank page, with no content and no transparency, the saved file still contains it. On a PDF/X-1a file that is wrong twice over: a transparency feature on a PDF 1.4 file, and a DeviceRGB colour space in a CMYK-only standard. Removing the key through the object model achieves nothing, because the writer puts it back on the next save, so the groups are now taken out of the finished file instead. The replacement is byte-for-byte the same length (spaces are legal whitespace between PDF tokens), which keeps every cross-reference offset valid rather than forcing a full xref rebuild.
- **A library change can no longer produce a file that lies about its conformance.** Stripping those groups depends on how PdfSharpCore serialises pages, so the packaging path re-reads the file it has just written and fails the export if any transparency survived. A future library update that breaks the technique now surfaces as a refused export rather than as a PDF/X-1a file with a transparency group inside it.
- **The "what to fix first" panel gave generic advice for 47 of 60 findings.** Actions are resolved by issue code, and the advice vocabulary had drifted from the codes the validators actually emit — eight templates carried names nothing could produce (`MIXED_COLOR_SPACE` against the real `MIXED_COLOR_SPACES`, `SPOT_COLOR_FORBIDDEN` against `SPOT_FORBIDDEN`, `IMAGE_DPI_VERY_LOW` and `IMAGE_DPI_HIGH` against `IMAGE_DPI_LOW` and `IMAGE_DPI_OVER_MAX`, plus `RGB_IN_CMYK_TARGET`, `TRANSPARENCY_FLATTEN`, `PDFX_NONCONFORMANT` and `FONT_SUBSET_INCOMPLETE`). Both sides were internally consistent, so nothing failed and nothing logged: the panel an operator reads first simply stopped advising, and every finding added since — the whole 1.5.8 prepress set, including every error-severity one — fell through to "N issue(s) detected, see the list below". Every code now has its own imperative in both languages, the dead templates are gone, and a test compares the two vocabularies so they cannot drift apart again.
- **Strict preflight refused ordinary booklets.** In headless and CLI runs the switch aborted on `Issues.Count > 0`, which counted the informational notes — and two of those describe entirely normal production. `SIGNATURE_PADDING` fires whenever a booklet's page count is not a multiple of the signature, which is precisely what the saddle strategy exists to pad; `DUPLEX_ODD_PAGES` fires on any odd-page duplex job. A six-page A5 booklet on an eight-page signature therefore failed a strict export, making the switch unusable for the automation it was built for. Errors already stop an export unconditionally, so what strict adds — and all it now adds — is warnings; the abort message also names the codes rather than saying "warnings present".
- **A trim mismatch reported once per page.** Every other rule aggregates, but this one emitted a row for each offending page — and a document whose trim does not match the template usually mismatches on all of them, so a forty-page job buried the rest of the report under forty identical lines. It is now one finding: the first offending page carries the measured numbers, the page list carries the extent.
- **The template-suggestion dialog cut its cards off, on both axes.** Horizontally, nine of the card's text fields had no wrapping: a product name carries its dimensions ("Notes / kalendarz A5 — spirala (148×210 mm)") and shares its row with the confidence badge, so at the dialog's width it ran off the card instead of breaking onto a second line. Vertically — and this is what an operator noticed — the list put its inset on the ScrollViewer as `Padding="16,12"`. A ScrollViewer subtracts its own padding from the content it measures without adding it back into the scrollable extent, so the extent came out 24 px short of the list: scrolled all the way to the bottom, the last card still hung 36 px below the viewport with no way to bring it into view. The inset now sits on the content as a margin, where it is measured as part of what scrolls. The same attribute was doing the same thing to the marks-profile editor and the preflight report, whose last finding was the one being cut.

### Changed
- **The ink-coverage scan is native, and the code now says so.** The scan itself has run on PDFium plus a real ICC transform since 1.5.0, but it still lived in a class called `GhostscriptInkScanner`, which also carried an unused Ghostscript `inkcov` implementation. The dead code is gone; the coverage model and the warning threshold moved to `NativeInkScanner`, where they belong, and Ghostscript discovery moved into a `GhostscriptLocator` that does only that.
- **Ghostscript discovery no longer looks for a bundled copy.** It searched two paths inside the installation directory for a copy that is not shipped — Ghostscript is AGPL software and cannot be redistributed inside a commercial closed-source product. It now looks where a user-installed copy actually lives: the configured path, then `PATH` (which the previous implementation never checked, despite the in-app help telling operators to add it there), then the standard `%ProgramFiles%\gs` layout.
- The export dialog no longer describes the native engine as "X-4 only", and the preflight advice for X-1a / X-3 transparency now distinguishes the inert constructs the engine removes by itself from transparency that genuinely paints.

### Tests
- 32 new tests. The two that matter most compare vocabularies rather than behaviour: every emitted code must have advice, and every piece of advice must belong to a code something can emit. Each side of that pairing was self-consistent while being wrong about the other, which is exactly the shape of defect no single-sided test can see. Also pinned: action templates use only the two arguments the generator supplies (a template reaching for a third throws while the operator is reading the report), the policy enum's values line up with the severities they stand for (the mapping is a cast), and informational findings never gate a strict export. The scrolling pair is behavioural plus structural: one scrolls the suggestion list to its end and asserts the last card is inside the viewport, the other forbids vertical padding on any ScrollViewer in the UI, since the mistake is one attribute away in every dialog and fails silently until the content outgrows the window. The headless test app also loads FluentTheme now — without it a ScrollViewer has no ScrollContentPresenter and quietly clips instead of scrolling, which is why this suite could not see the defect. The panel handles are pinned structurally, because what makes a collapse work is where the fixed width is written — on the panel, never on the grid column — and markup that gets that wrong looks correct while giving the canvas nothing back.

## [1.5.11] - 2026-08-30

Folded leaflets stop being sized by the press sheet. The panel width now comes from the product the operator entered, the way it does for every other binding, and both the item size and the sheet size can be picked from the standard-size list.

### Fixed
- **Fold panels were spaced by dividing the sheet, not by the product size.** Z-fold, accordion and gatefold derived their panel width as `(sheet − margins − gutters) ÷ panels`, and the trim size was only a rectangle the artwork was fitted into, centred inside whatever that division produced. The fold lines therefore moved whenever the stock changed: a DL leaflet (panels 99 mm) imposed on SRA3 came out with its panels 143.33 mm apart, so a folder creasing at 99 mm creased through the artwork. There was no way to say "the product is A4 folded to DL" — only the sheet was an input, which is exactly backwards for a product whose geometry is fixed by the finishing machine. Panels are now laid out at the entered size, touching at the fold lines, with the whole block centred on the sheet and the leftover paper left blank. `FoldGeometry` is the one place that computes this, shared by the strategy, validation, the preview and the marks renderer, so all four agree on where the sheet gets creased.
- **A fold whose panels overran the sheet validated clean.** Only gatefold had a fit check; Z-fold and accordion fell through to the generic N-up test, which — with the `NUpX = 1` every fold preset ships — asked whether ONE panel fits. Three panels of 210 mm on a 297 mm sheet passed validation and reached the strategy, which produced panels overlapping by 114 mm, the first starting 52 mm off the left edge of the paper and the last overhanging the right. All three folding bindings now share one check (`panels × panel width + gutters + margins` against the sheet, plus the panel height), and it names what it measured: *"3 panele po 210,0mm"* or *"wyrób rozłożony 297×210mm = 3×99,0mm"*.
- **The built-in DL Z-fold preset was internally inconsistent** — an A4 landscape sheet with a 210 × 99 mm trim, i.e. the case above — and shipped that way. It is now an A4 landscape product (entered as the unfolded leaflet) on SRA3, giving the 99 × 210 mm panels the name promises. The DL accordion moves to a 10 mm sheet margin so its four panels sit inside the stock, and the two US fold presets are marked as what their code comments already said they were: flat Letter products, so the tri-fold's panels resolve to 93.1 mm instead of being read as 279.4 mm panels.
- **The size dropdowns did not follow the template they describe.** The paper list and its landscape tick were only re-pointed at the template by *Load*, *New* and the preset buttons; on startup, and after any other swap, the tick stayed at "portrait" while the template held a landscape sheet. The next size picked from the list therefore came out rotated against what the operator was looking at. Both dropdowns (sheet and item) now re-sync on every template change, including the one the editor opens with.
- **Fold marks were only ever drawn for saddle stitch.** Every fold preset ships with fold marks enabled, and neither the preview nor the exported PDF showed a single one for a folded leaflet — the one binding whose name is about folding. Dashed ticks are now drawn at the top and bottom edge of each crease, at the positions the panels actually meet, in the preview and in the PDF alike. Saddle stitch keeps its spine mark.
- **A pitch-spaced Step & Repeat grid that overran the sheet validated clean.** In centre-to-centre mode the strategy centres a block of `(N−1) × pitch + item` on the sheet and ignores gutter and sheet margin — but the only sheet-fit check that ran was the generic margin/gutter formula, which describes a different layout. A 4-column grid of 50 mm stickers at a 60 mm pitch on A4 (230 mm needed, 210 available) passed validation and printed with the outer columns cropped at the sheet edge; conversely, a valid pitch template with a non-zero sheet margin could be rejected for space the strategy never uses. Validation now checks the pitch grid against the sheet exactly the way the strategy lays it out, and the generic formula no longer applies to that mode.
- **The US accordion preset produced 2.13 × 11″ strips.** It folded a portrait Letter across its 8.5″ width into four tall, narrow panels — a shape no folder rack expects. It now matches the tri-fold preset's orientation: flat Letter landscape on 11×17, four standard 2.75 × 8.5″ panels.
- **Leaving Ganging could strand a template in work-and-turn.** The duplex-mode combo is only meaningful for Ganging, but the selected mode survived a binding switch, and OK then failed validation on a value the operator had no visible control for. The mode now resets to sheetwise when the binding stops being Ganging, and the combo is shown only where it applies (duplex Ganging). Flipping the duplex checkbox also updates that row live — it previously refreshed only when the whole template was swapped.
- **Five suggestion-library products shipped on a sheet their own bleed could not fit.** The B2, Tabloid, ANSI C and ANSI D poster presets paired the poster with a press sheet of the very same size, and the Half-Letter flyer (as wide as a Letter sheet) tried to gang on Letter — every one of them built a template that failed validation the moment the operator applied it. Posters now run on a sheet one class up (B2→B1, Tabloid→ANSI C, ANSI C→D, D→E), the Half-Letter flyer gangs 2-up on portrait Tabloid, and a new test feeds every library entry its own canonical size and asserts the resulting template validates — so this class of bug cannot ship again.

### Added
- **The item size can be picked from the standard-size list, like the sheet already could.** The trim card gets the same dropdown and landscape tick as the sheet card, over the same registry — so custom sizes added there appear here too, and persist across restarts as before. Typing dimensions by hand re-selects the matching standard size or clears the selection rather than leaving a name that lies about the item. This applies to every binding, not only the folded ones.
- **Folding templates can be described either way round.** A new *Entered size is* selector on the fold card reads the trim as **one panel** (the page size of the incoming PDF) or as the **unfolded product** — "A4 folded to DL" being the way most jobs arrive — in which case the panel is the width divided by the panel count. Templates written before this release deserialize as *panel*, which is what their trim already meant, so existing sheets are unchanged.
- **The quick-start presets were renamed around the product and grouped by kind.** Two dozen entries in one flat column, named after the mechanism ("A4 Ganging 2-up", "DL Ulotka Z-fold"), asked the operator to translate binding jargon into the job on their desk. Every preset now leads with the product and the finished size — *"Ulotka DL — falc Z, 3 panele"*, *"Wizytówki 85×55 mm — 12 na arkuszu"*, *"Broszura A4 — zeszytowa"* — and the list is split under four headings: booklets & books, folded leaflets, multiple items per sheet, labels & stickers. The sub-line under each name states what actually gets produced, verified against the preset's own parameters rather than inherited from an older revision: *"SRA3 poziomo → A4 poziomo złożone na 3 panele 99×210 mm"*.
  - Three descriptions had gone stale and were saying the wrong thing: the DL Z-fold still advertised an A4 sheet after this release moved it to SRA3, and the A4 sticker preset claimed a 55 mm pitch where the template carries 52 mm.
  - **The list says out loud that its numbers are a starting point.** A sub-line reading "SRA3 landscape → A4, 8-page signature" describes the preset the way a product spec describes a finished job, which invites the reading that clicking it locks those sizes in. The section is now headed *Starting points* with one line under it — the sheets and formats listed are starting values, changeable before the template is saved — every preset's hover text repeats it, and the status line after a click says the parameters are yours to adjust. The descriptions keep their exact numbers: what the preset actually sets is worth knowing before clicking it.
  - A preset whose category key matches no heading would silently vanish from the picker, so the catalogue is pinned by tests: every preset reaches exactly one group, and every name, description and heading exists in both languages.

- **The fold card shows what the numbers resolve to**: panel size, unfolded size, and the panel block against the sheet width, with a warning when the block does not fit. That is the readout an operator needs before sending 500 leaflets to a folder set to fixed positions.

- **The template manager gained a live sheet preview.** A third column draws a schematic of the first press sheet — item slots with their page numbers, blank slots, fold lines where the folder will crease, the usable-area margin — refreshed as the operator types, with a per-sheet yield line (items × coverage) underneath. It is planned by the very same binding strategies that plan production, so the thumbnail cannot drift from what exports; roll previews clamp to a readable handful of rows, and an invalid template degrades to a plain "fix the errors above" note instead of a stale drawing.
- **Validation runs live, not only on OK.** The error banner now appears while the operator is still editing — and clears the moment the field is fixed — instead of waiting for *Use template* to be clicked. The refresh is content-guarded, so the banner never flickers on a quiet tick.
- **Every binding type now has a starting point.** Wiro and gatefold were the two bindings with no preset — invisible to an operator browsing the quick-start list. Four new entries: *Notes A5 — spirala (wiro)* (4 × A5 on portrait SRA3, cut → punch → bind) and *Ulotka altarka — 4 panele 100×210 mm* (400 × 210 mm unfolded, doors narrowed 2 mm) in the metric set; *Half-Letter notebook — wire-o* and *Gatefold leaflet 17×11″* as their US twins. A test now pins the rule: each `BindingType` must be reachable from at least one preset in both unit sets.
- **The preset catalogue is proven valid by tests, not by comments.** Every factory's hand-written fit proof is now executable: each preset must pass `Template.Validate()`, carry a unique id, and survive a JSON save → load round trip unchanged.
- **DL and the business-card sizes joined the standard-size registry** (DL 99 × 210, BC 85×55, BC 90×50, BC US 3.5×2″), so the item-size dropdown names what the presets set instead of clearing.
- **The signature spinner hides for bindings that ignore it.** *Pages per signature* only drives saddle stitch and perfect binding; for ganging, wiro, folds, roll and step & repeat it was a spinner that did nothing.
- **About lists the project's addresses.** The website and the GitHub repository are now clickable in the About box, with the address itself as the caption so it stays readable (and typeable) on a machine with no browser configured. The website URL is a localisation key rather than a constant, so the Polish interface opens the Polish site and the English one opens `/en/` — a test pins both languages, checks each address really parses as an https URL (a "translated" or typo'd URL would leave the button silently doing nothing), and asserts the two languages still point at one repository.
- **Template suggestions got materially smarter.**
  - **Bleed detection.** A PDF that hands over its MediaBox instead of a TrimBox arrives as trim + bleed — an 85×55 card as 91×61 — and used to be answered with a shrug of near-misses. When the raw size snaps to nothing but "size − 2×bleed" snaps *exactly* (tried at 3, 2 and 5 mm, within a deliberately tight 1 mm band so a legitimate custom size is never re-read as someone else's product), the engine corrects the input, builds the template on the true trim with the detected bleed, and says so on the card: *"Wymiary pliku zawierają spad ~3 mm — jako format użytku przyjęto 85×55 mm."*
  - **Distance thresholds now scale with the format.** The fixed 25 mm search radius located business cards perfectly and made posters unfindable — a B1 file 30 mm off nominal got "no matches". Both thresholds keep their old values as floors and grow with the input's diagonal (5% for the search radius, 0.3% for the exact-snap band), so card-scale behaviour is untouched while poster-scale files finally resolve.
  - **New products**: wire-o notebooks/calendars A5 and A4 (offered alongside the saddle-stitch booklet from 5 pages up — the operator knows which finishing line the job goes to), the 4-panel DL accordion and the 4-panel gatefold *altarka* (gated to 7-8-page documents so they never crowd the 6-page Z-fold), posters A1 and B1, and the 105×297 rack leaflet. ## [1.5.10] - 2026-08-08

Ganging stops being a copier. The N-up grid can now carry the document's consecutive pages instead of the same page over and over — the difference between imposing a 5-page job and imposing page 1 of it five times.

### Added
- **Source pages can be reordered by dragging their thumbnails.** Drag a page in the preview strip to a new position and the loaded document is rewritten in that order, so it is what gets planned, imposed, exported and saved — there is no separate "apply" step to forget. A banner appears once the order has been touched, with a *Restore order* button back to the natural sequence.
  - **The drag says where the page will land.** The tile follows the pointer as a ghost, the tile it came from fades so its origin stays visible, and an insertion caret marks the exact gap the page will drop into — a wrapped grid of look-alike tiles otherwise gives the operator nothing to aim at. The caret overlays the tile rather than occupying columns of its own: reserving space for it widened every tile by 6 px, which at the inspector's width was enough to push a tile onto the next row and break up the strip. An indicator that only appears mid-drag must not change the layout it is pointing at. The caret sits on one side of a tile while the move removes the page before re-inserting it, so the index arithmetic that keeps the caret's promise is pinned by tests: an off-by-one there lands the page one slot from where it was aimed and reads as the feature simply being inaccurate. A page dropped outside the strip cancels the drag instead of being answered with "only PDF files are accepted".
  - **The order survives the page edits that rebuild the document.** Rotating or converting a page re-assembles the loaded document from the source files, in file order, so the arrangement is held as a permutation and re-applied after every assembly rather than by rewriting whatever file happens to be loaded. Otherwise an operator would reorder, rotate one page, and get their arrangement silently reverted — noticed on the printed sheet.
  - **Saving honours the order too.** *Save PDF* reads a source file rather than the loaded document, and *Merge and save* re-merges from the file list — both would have handed back the original sequence. A manual order belongs to the loaded document, so when that document is the file being saved, the save reads it; the redirect is scoped to exactly that case, and a per-file save otherwise stays a per-file save.
  - Page edits address physical pages while the strip names positions, and after a move the two numberings differ. Rotating "the first thumbnail" now rotates the page that is actually first, not the one that used to be. A permutation whose length no longer matches the document is dropped rather than applied: the set of pages changed underneath it, and a stale permutation would scramble the job instead of preserving an intent.

- **The in-app help was rewritten against what the app actually does, in both languages.** It still described a three-binding, session-only-custom-sizes version of the program. Ten sections are new — the step bar and what each numbered step really opens, source files and per-page edits, ganging slot modes, layout optimisation and the sheet advisor, template suggestions, hand-editing slots, marks profiles, preflight (both levels, the five press profiles, and which findings have repairs and which deliberately do not), hot folders, and application settings — and the existing ones were brought up to date: all nine bindings instead of three, the current export dialog, preview tools including separations, eyedropper and the registration overlay, and a glossary that now covers ganging, work-and-turn, TAC, trapping, output intents and the PDF/X flavours. Two stale claims are gone: custom paper sizes persist across restarts, and the shortcut table lists the undo/redo and F1 keys the app has had for a while. A test pins every help key to both dictionaries, because a section translated in one language reaches the operator as a raw key in the middle of the manual.

- **Ganging can now fill its slots with consecutive document pages, not only with copies of one.** Ganging had exactly one behaviour: every slot on a sheet carries the same source page, with duplex pairing pages 1-2 onto the front/back of sheet 1, 3-4 onto sheet 2, and so on. That is right for a business-card run — one design, twelve copies, verso on the back — and wrong for the thing the presets are named after: a 5-page document ganged 2-up came out as three sheets of one page repeated, with half the document on versos and the operator convinced pages 2 and 4 had been dropped. **ConsecutivePages** fills the slots in reading order instead: 1+2, 3+4, 5. With duplex each slot becomes its own leaf (odd page recto, next page verso, X-mirrored so it backs up after a long-edge flip), and work-and-turn pairs each product across the fold rather than repeating one.
  - **Nothing changes for templates that already exist.** The mode defaults to RepeatItem, which is what every saved template and every hot folder has been doing; a template written before this release deserializes into exactly the press sheets it produced yesterday. The multi-page gang presets — A4 2-up, A5 4-up and their Letter / Half-Letter twins — ship with ConsecutivePages, because "2× A4 on the sheet" has always meant two different A4s. The business-card, DL-leaflet and rack-card presets stay on RepeatItem: those are single-design runs.
  - The template manager grows a *Ganging* card explaining, in one sentence per mode, what the current setting does to a multi-page document — the question the old behaviour raised and never answered.

### Changed
- **Switching language or units now changes what is on screen immediately.** The setting was already pushed into the running app; what did not work was the binding almost every caption in the program uses.
  - **`{loc:Loc}` had never followed a language change at all.** The markup extension bound to the localisation service's INDEXER and relied on a WPF-style `PropertyChanged("Item[]")` notification, which Avalonia does not treat as invalidating an indexer path. Every menu, button, label, tab, dialog and tooltip in the application rendered correctly on first paint and then froze in the language the app had started in — for the life of the process. Only the handful of view-model properties that notify by name ever updated, which is exactly why this read as "some of the interface changes" instead of "the mechanism is dead". The extension now binds to a plain property that really does raise PropertyChanged and maps it to text through a converter, so one change fixes every caption in the app; `{loc:UnitLabel}` had the same broken leg and gets the same fix. A headless test drives a real bound control through a language switch, because the defect was invisible at every level above the binding engine.
  - Text that no XAML binding covers had to be pushed by hand, and now is: the sheet canvas repaints and drops its composed scene (the old wording was baked into the bitmap), the preview's front/back labels re-emit, and source-page captions are retranslated in place rather than by rebuilding the strip, which would have thrown away every rendered miniature to change a caption.
  - Readouts that resolve through a **converter** — the "no template" placeholders on the step bar and the template card, the Yes/No duplex line — only re-run when their binding source changes, so they are nudged explicitly. The "Load checked (3)" caption and the licence badge follow too: the badge is now composed from the licence *facts* held in the view-model instead of a sentence built once at startup.
  - The idle "Ready" greeting follows the language; a status message about something that happened does not. "Loaded 12 pages" was true in the language it was written in — retranslating a record would be a small lie, and the settings hint now says so instead of promising a restart nothing needs.
- **Step (4) is now called "Export settings", not "Export".** It opens the options dialog; the green button on the right of the same bar is what writes the file. Two buttons a hand's width apart, both labelled export and only one of them exporting, is a trap the step bar laid every time. The numbered step also loses its ▶ glyph, which read as "run this" right next to the button that actually does.

### Fixed
- **Editing a slot moved the outlines but not the page.** Position, size, rotation and source-page changes in the inspector reached the plan correctly and then appeared to do nothing: the canvas caches its whole composed scene into one bitmap and re-blits it while nothing in its snapshot key changes, and that key carried the sheet NUMBER but nothing about the sheet's content. An edited sheet therefore looked identical to the cached one. The guides and the selection outline are recomputed every frame and did move, which is exactly why this read as "only lines show, physically nothing happens to the image". The cache now compares the sheet instance itself, which every edit path — including undo and redo — replaces rather than mutates.
- **Rotating a page right and then left left it permanently landscape.** The rotation is applied to a working copy by changing the page's `/Rotate`, and writing that through PdfSharp's page wrapper makes the library resolve the page's VISUAL size and bake it into the MediaBox on save. So the round trip came back to `/Rotate 0` on an A4 whose box had become 842×595: the content was upright again, the sheet was not. Measured on a portrait A4 — right then left used to yield `media=842×595`, and now yields `595×842`, identical to the original. The rotation is written straight into the page dictionary instead, which leaves the geometry exactly as the file declared it; the page-tree walk that finds the page also handles nested `/Pages` nodes and inherited `/Rotate`, both of which a flat lookup got wrong on documents assembled from several sources.
- **A freshly loaded document stayed soft until the "Str. N" badge faded.** Two independent defects, and the badge really was implicated in one of them.
  - **The canvas kept blitting a stale composed scene.** The canvas caches its whole composed scene into one bitmap and re-blits it while nothing relevant changes. It flagged that cache as provisional when a page had drawn a *loading placeholder*, but not when the page had drawn a **stand-in bitmap from another scale** — so a scene painted with a 150 px thumbnail blown up to full size counted as final. The completed full-resolution render then had nothing to invalidate, and the soft scene stayed on screen until some unrelated part of the cache key changed. On a freshly loaded document the only thing that changed on its own was the page badge's fade phase, two seconds later — which is exactly when operators saw the preview snap into focus. Stand-ins are now flagged like placeholders, so the real render replaces them the moment it lands.
  - **The thumbnail strip cancelled the canvas's render.** The canvas and the strip share one renderer and ask it for the same page at wildly different sizes — display resolution against 150 px — but it kept a single "newest scale wanted" slot per page. Every thumbnail request marked the canvas's full-resolution render stale; that render bailed out at the concurrency gate. The strip re-requests its visible window on every completed render, so this repeated until the whole strip was cached. Requests now declare which lane they belong to and the two no longer cancel each other. Measured on a 595×842 page: the shared slot left a 446 px bitmap where the canvas had asked for 2677 px.
- **"Optimize N-up" left the N-up fields showing the old grid.** The optimiser wrote the new layout straight into the template, which is a plain object with no change notification, so the status bar announced "4×5" while the spinners next to it still read "4×3" — and the operator had to retype the numbers the button had just computed. The fields now follow the template. Their upper bound moves from 16 to 100 at the same time: a small item on a large sheet genuinely gangs past sixteen rows, and a spinner capped at 16 would have quietly written that cap back over the computed layout the moment it started refreshing.
- **Clicking a source-page thumbnail threw you out of the source-page list.** The canvas jumping to the sheet that page landed on is the point of the click; switching the navigator to the *sheets* list as well meant the operator lost their place after every single click and had to switch tabs back to look at the next page. The canvas still jumps, the sheet tile is still highlighted, and the list you are browsing stays put.

## [1.5.8] - 2026-08-03

Template suggestions stop being a distance ranking and start being a recommendation: six weighted signals, an explanation for every entry, and a memory of what this particular shop actually prints.

### Added
- **Template suggestions are ranked on six weighted factors instead of dimensional distance alone.** Distance still dominates by design — an operator picked the product their PDF *is*, not whatever packs densest — but proportion agreement, page count, sheet fit, workflow fit and how product-specific a preset is now all contribute. Every weight lives in one place as a named constant, and the six sum to exactly 1.0, which a test enforces so a future edit cannot quietly move every quality band.
  - **Sheet efficiency is deliberately barred from reordering products.** A 90×50 business card and a 90×50 roll label are the same size and gang completely differently; letting yield decide would swap the product under the operator. It contributes to the score shown on the card and to nothing else. Yield comparisons are only meaningful across sheets for *one* product — which is what the alternative-sheet panel is for.
- **Every suggestion now explains itself.** Each card carries a short checklist — "dimensions match to the millimetre", "page count suits this product", "fits your current sheet and binding", "matches your measurement system" — built only from reasons that actually hold. A checklist padded with weak entries teaches operators to stop reading it, so a preset whose proportions merely happen to agree does not claim that as a reason when the dimensions already matched exactly.
- **Alternative press sheets are suggested when they would yield materially more items.** A card whose layout leaves half the sheet empty now says which other sheet would gang it denser, with the item count and the improvement factor. **It never changes the sheet the suggestion applies** — which sheet a shop runs depends on its press, its stock and its finishing, none of which the engine can see. It makes the trade-off visible and leaves the decision where it belongs. Roll-fed products are excluded: segment length is derived, not chosen, so "a bigger sheet" is not something the operator can act on.
- **Products are categorised and the library list is grouped by category.** Business cards, leaflets, booklets, posters, labels, stickers, tickets, hang tags and the rest each get a heading, ordered by their best-ranked member so the most likely product still comes first and nothing is reordered within a group. "Show me the other labels" is a real question and it used to require reading a flat list of forty entries.
- **Four match-quality grades instead of two.** Exact / Close is still what the engine reports to any existing caller — that contract is unchanged — but the card now shows Perfect, Excellent, Good or Worth checking, so a near-tie and a stretch no longer look identical. A dimensional snap can never be graded below Excellent: being the same size as the product is the strongest evidence available, and no combination of weaker signals should talk us out of it.
- **The engine learns which preset this shop picks for a given size.** Open an 85×55 file, choose "Business card", and the next 85×55 file ranks that preset higher. Three deliberate picks for the same size is already a habit rather than a coincidence, so the bonus reaches full strength quickly — and it is capped low enough that learned habit can promote a near-tie and never override a clear dimensional mismatch. A shop that has printed a hundred business cards must still be told when the file in front of them is an A4 leaflet. Sizes are bucketed, so an 85.04×54.98 export of the same card feeds the same history entry rather than building a second half-strength one, and a rotated PDF matches the same entry.
  - **It persists.** The history is written to `suggestion-preferences.json` in the roaming profile and survives closing the app — a preference that had to be relearned every morning would be the same as no preference at all. Nothing leaves the machine, and *Settings → Suggestion learning* shows how much has been remembered with a button to forget all of it, for the shop that changes press or product mix.
  - **It can change its mind.** Counts are capped at the saturation point and every rival preset for that size loses a point when another is chosen, so switching from cards to labels at 90×50 takes the same three deliberate picks that established the old habit — rather than having to outvote a tally that has been growing for a year. A hand-edited history file cannot buy an unbeatable preference either: counts are clamped on load.

- **Creep compensation accepts grammage instead of caliper.** The paper can now be described the way it is actually quoted — "90 gsm" off the ream wrapper — rather than by a thickness nobody has measured. One or the other is authoritative, never both: picking a mode disables the other input and the imposition reads a single resolved figure, so two half-remembered numbers can never disagree.
  - **Grammage needs the paper family, and that is not a formality.** Mass per square metre says nothing about thickness on its own: 90 gsm gloss art is about 0.072 mm while 90 gsm bulky book paper is about 0.162 mm — more than twice as thick. Creep is a shift applied to page content, so a 2× error moves artwork further from correct than switching compensation off would. Five families ship with their mid-range bulk (gloss art, silk, uncoated offset, recycled, bulky), and *Custom* takes the figure from the mill's data sheet.
  - The dialog shows what the description resolves to — "0.117 mm (117 µm)" — in both modes, so the conversion is visible rather than implied, and a setup that resolves to nothing is refused at validation instead of silently imposing without compensation.
  - Existing templates are untouched: they carry only a thickness, the mode defaults to thickness, and they impose exactly as before.
- **Preflight now checks the safe zone.** Text that crosses the trim line is reported as an error; text that clears the trim but sits closer to it than the safe zone is a warning. A guillotine works to a few tenths of a millimetre and a clamped stack shifts, so text 1 mm from the edge survives the proof and loses its last character somewhere in the middle of the run — the single most common reason a job comes back. Only **text** is measured, never the combined content box: a background running past the trim is the entire point of bleed, and testing against it would raise a finding on essentially every correctly-prepared file. The template's own safe zone wins when it declares one, because a hang tag punched near the edge needs more room than a business card.
- **Preflight now checks total area coverage against the press limit.** Too much ink in one place does not dry: it sets off onto the back of the next sheet, blocks in the delivery, and on a web can pick the paper apart. It is one of the few defects that ruins the whole run rather than one copy, and nothing in preflight looked for it. A small heavy element is a warning; the same coverage over a postcard-sized area, or anything a fifth past the limit, is an error.
  - **The numbers are read from the file, not measured from a render.** The check uses the CMYK values the content stream actually declares, so a panel authored at 370% reports 370%. Recovering that from a rasterised page is not possible even in principle — rendering flattens to RGB, and converting back to CMYK rebuilds near-black as mostly K. Measured against this release's own test file, the same 370% panel comes back at about 105% through the raster route. An ink check built that way would quietly clear files that flood the press, which is worse than having no check at all.
  - **It says what it did not look at.** Placed images carry their own pixels and are not inspected, so when a flagged page also contains images the report says so rather than implying the page was cleared. The on-demand coverage scan in the file-info dialog keeps its place as a relative "which page is heaviest" signal and now states plainly that its averages under-report.
- **Preflight now checks how black is built** — two opposite mistakes, both worth a rerun. Small text set in a four-colour black shows every registration error as coloured fringing and belongs in K alone; a large solid in flat 100% K with nothing underneath dries to a washed-out, mottled grey and wants support from the other separations. Reported, never repaired: the right support values depend on the press, the stock and the ink limit, and a designer may have chosen flat K deliberately to keep a fold or a barcode clean.
- **Preflight now reports trapping — strictly what the file says about itself.** Three facts, each of which changes what happens next: whether the document declares a `/Trapped` state at all (PDF/X-1a and PDF/X-3 require an explicit True or False, and "Unknown" is reported separately from "nobody set it"); whether trap networks are already baked into the pages, which are tied to the separations and resolution they were built for and go stale when colour is converted or the job is re-imposed — and which PDF/X-4 does not permit at all; and whether a file that declares itself untrapped is carrying spot colours, since spot-to-process boundaries are exactly where a registration error shows as a white line.
  - **It does not decide where a trap belongs, and does not pretend to.** That means comparing every pair of adjacent objects for shared separations across the whole page — a trapping engine, not a preflight rule. A check that guessed at trap placement would be wrong in the direction that costs a reprint, so this one stays inside what it can actually know.
  - Single-separation work is exempt: one ink cannot mis-register against itself, and flagging greyscale jobs would be noise on exactly the jobs that can never benefit.
  - The spot-work warning is a per-profile switch, on for the three offset profiles and off for digital and large format. Shops that trap at the RIP would otherwise be told about every spot job they ever open, which is how a rule earns a reputation for crying wolf.
- **Fixed: the annotation repair could strip a file's trapping.** It cleared the entire `/Annots` array, and trap networks and printer marks live there alongside comments and form fields — so asking it to clean up mark-up could silently remove the trapping the file was prepared with, or the registration marks and colour bars placed as annotations. It now removes only interactive and mark-up annotations and keeps production ones, including any annotation it cannot identify: the cost of keeping a stray comment is cosmetic, the cost of dropping unrecognised trapping is a reprint.
- **Preflight now catches the same spot colour spelled several ways.** `PANTONE 185 C`, `PANTONE 185C` and `Pantone 185 C` in one document are three separations to a RIP — three plates and three wash-ups for an ink the shop ordered once. A file assembled from a client logo, a finisher's die line and an older panel gets there without anyone doing anything unusual, and it is normally discovered at make-ready. The stock suffix is deliberately **kept**: 185 C and 185 U are genuinely different inks, and folding them would turn a typo-catcher into a source of wrong advice.
- **Preflight now reports layers, and specifically when they disagree with themselves.** A layer switched off in the viewer can still be marked to print — which is how a "client comments" or die-line layer nobody can see on the proof ends up on the plate — and equally a visible layer can carry `PrintState /OFF`, so what was approved on screen never reaches the press. Both are reported with the layer names, the first as an error. The basic analysis has always known *whether* a file has layers; knowing *which* one and whether it prints is what an operator can act on.
- **Preflight now flags image encodings a RIP may refuse.** JPEG 2000 and JBIG2 are legal PDF and render perfectly in every viewer, which is exactly why they reach platesetting unnoticed; plenty of production RIPs still refuse them, PDF/X-1a forbids JPEG 2000 outright, and they are also the formats this app's own RGB repair cannot convert. 16-bit images are noted separately — valid, occasionally deliberate, double the data for a precision no press can hold.
- **The suggestion library takes your own products.** *Settings → Your own products* adds a signature folded card, a customer's fixed label size or the die-cut half the town orders, with its own name, size, category and press sheet. They appear alongside the built-ins, group under the same headings and take part in the same learning.
  - This closes a gap this release opened. 1.5.8 taught the ranking to learn which preset a shop prefers — but only among the forty built-ins, so a 100×210 folded card still came back as "Ticket" or "Bookmark", the operator picked the least-wrong entry, and the engine dutifully learned the wrong name and saved it onto the template. Learning preferences without being able to add products was half a mechanism.
  - Your products default to belonging to no measurement system, so they stay visible whether you work in millimetres or inches — hiding an operator's own product from them would be indefensible. Adding a product with an existing name updates it rather than creating a rival for the same size, and the name is the product's identity: renaming starts its learned history over.
- **Prepress profiles.** The thresholds preflight judges files against are now a named, editable set instead of constants in the code — ink limit, safe zone, the three resolution bands, and the colour and black policies. Five ship with the app, covering coated and uncoated sheet-fed offset, newsprint, digital and large format, with the ink limits and resolution floors each process actually calls for. A banner at 120 dpi is correct work, and judging it by the floor that suits a business card was rejecting every properly-prepared large-format job.
  - A profile describes the **press**; the template and export options still supply what belongs to the **job** — expected trim, bleed depth, PDF/X target. Keeping the two apart is what lets one profile serve every job on that press instead of being welded to the dimensions it was created with.
  - Editing a built-in and saving produces a profile of your own; the shipped ones cannot be overwritten, so a future release can still correct a threshold everywhere. Deleting the active profile falls back to the default rather than leaving preflight without one.
- **Hot folders can run the full prepress inspection**, with their own profile — the folder that accepts customer artwork can be strict while the folder fed by a known-good system stays fast. Off by default on purpose: the deep inspection re-parses every file, and 1.5.7 spent real effort removing exactly that kind of duplicate parse from the pipeline. Findings go to the log; they stop a job only when *Strict preflight* is also on, so switching the inspection on never changes what passes — only what you are told.

### Changed
- The settings dialog scrolls instead of clipping. It grew a prepress-profile card this release and no longer fits on a short screen; it still shrinks to its content when there is room.
- Suggestion cards show the match grade next to the confidence percentage, coloured from the grade rather than the raw number so the word and the colour can never disagree.
- **The suggestion engine still does no prepress validation.** Bleed, safe zones, crop marks, page errors and printability remain entirely Preflight's job — a second opinion from a size-matching engine would be a worse one, and two components disagreeing about whether a file is printable is how operators learn to trust neither.

## [1.5.7] - 2026-07-31

One place to browse a job: the sheet strip moves into the inspector, and a thumbnail click stops destroying the plan.

### Fixed
- **Preflight now reports RGB in vector artwork, not only in images.** The rule inspected image objects exclusively, so a file whose RGB lived in a logo, a tinted background or a chart — the common case — passed preflight completely clean and surprised the operator at export time. It is reported as a distinct finding, and the RGB repair handles it.
- **Applying a suggested template left the header reading "No template".** The suggestion engine built its templates with an empty name and a comment stating the UI would fill in the localised one — nothing ever did. An operator who had just picked "Leaflet A4" was told there was no template, and the imposed job still claimed none after planning. The name is now set when the suggestion is selected. It deliberately omits the dimension suffix the card shows: the template gets saved to disk, and a name baked with "in" reads wrong once the operator switches to millimetres — the dimensions live in the template itself and render in whatever unit is active.
- **Template suggestions now follow the unit preference.** A shop configured in inches was offered A4, DL and SRA3 products, even though the template editor's quick-start presets already switched to the US set on the same setting — the two halves of the app disagreed. Suggestions are now filtered to the matching family. Two deliberate exceptions keep the list useful: presets belonging to no national standard (roll labels, stickers, hang tags, tickets) always appear, and an **exact** dimensional match survives regardless of preference — a US shop opening a genuinely A4 file must still be told it is A4.
- **Tooltips and slot selection could land a few dozen pixels off for one frame.** On a frame that rebuilt the preview's scene cache, hit rectangles from the cache-drawing pass (in cache coordinates, offset by the overscan margin) were left in place alongside the correctly recomputed ones, so whichever matched first won. The stale set is now dropped before the rebuild.
- **An in-app update no longer kills the app mid-shutdown.** Accepting an update started the installer and immediately called `Environment.Exit`, which unwinds nothing: the application's exit path never ran, so pending diagnostics were dropped, the last log lines stayed in the buffer, and hot-folder jobs in flight were abandoned with their files stranded in `.work` and their ledger rows stuck at `reserved` until the next start recovered them. On top of that the installer was already running against the live process, racing its own teardown. The app now closes through the normal shutdown path — hot folders drain, telemetry flushes, logs close — and the installer is started only afterwards, against an idle installation. Its SHA-256 is re-checked immediately before launch, so a file swapped after download is refused instead of executed.
- **Feature-usage diagnostics were never actually sent.** The counters behind *Settings → Diagnostics* (export, template manager, hot folders, page edit, Save PDF, preflight) were incremented correctly and then died with the process: the only flush ran at startup — before the operator had opened anything — so every batch left the app with an empty `features` map. There was no periodic flush and no flush on exit, even though the code documented both. Counters are now pushed every 5 minutes and once more on shutdown, and a failed send hands them back to the queue so an offline spell no longer discards a whole session's usage. Empty batches are never sent.
- **Clicking a page thumbnail no longer throws away the imposition.** With a planned job on screen, a left click on a source-page thumbnail rebuilt the canvas in plain page-preview mode: the imposition disappeared, the sheet strip at the bottom of the canvas disappeared with it, and — unannounced — every manual slot edit (move / rotate / blank) was discarded along with its undo history. The click now jumps to the **sheet that page landed on**, flipping to the verso when the page only appears there, and leaves the plan and the edits untouched. A page that is not part of the plan (blanked slot, page range) reports that in the status bar instead of changing the view.
- Leaving the imposition for the plain page preview is now an explicit action ("Show source pages") that says up front when it is about to drop manual slot edits.

### Added
- **Preflight can now repair, not just report.** The file-info dialog's validation tab gained a Repairs panel offering only the fixes that apply to the file in front of you: **missing TrimBox / BleedBox**, **RGB → CMYK conversion** through an ICC profile, and **removal of annotations and form fields**. Each runs on a copy — the original is never opened for writing — and the result is written to a path you choose.
  - **The repaired file is re-checked and the outcome reports what actually changed**, listing the finding codes that are genuinely gone from the written file. A repair tool that says "3 fixes applied" is asking to be believed; this one shows the evidence, and says so plainly when a repair changed nothing.
  - Colour conversion reuses the very engine the PDF/X-4 export uses, so a repaired file behaves identically to an exported one. Without a CMYK ICC profile the repair is not offered at all rather than falling back to an approximation, and an image in an encoding the converter cannot read (JPEG 2000, 16-bit) is reported as unconverted instead of being passed off as CMYK.
  - RGB repair is offered even when the validator reports nothing: the RGB rule inspects images only, so vector artwork — a logo, a tinted background, a chart — never raised a finding. The repair scans the file itself.
  - Findings that cannot be repaired correctly in place — missing embedded fonts, low-resolution images, live transparency — deliberately have no fix. Guessing at them would put a plausible-looking wrong file on the press.
- **Hover descriptions for every production mark in the preview.** Pointing at a mark on the sheet now explains what it is and why it is there — crop marks, contour-cutter (OPOS) markers, registration marks, the control strip, fold marks, the slug line, the sheet barcode/QR, and the trim and bleed guides. Page slots already had a tooltip; the marks around them, which are the least self-explanatory things on the sheet, had none. Available in Polish and English like the rest of the interface. Marks take priority over the page slot underneath, so a hairline sitting on top of artwork is still hoverable.

### Changed
- **Sheet navigation moved from the canvas into the inspector's "Preview" tab.** The floating strip at the bottom-left of the canvas and the thumbnail grid in the inspector were two navigators that looked alike and behaved differently — one moved around inside the plan, the other tore the plan down. They are now one list behind an **Sheets / Source pages** switch, which selects Sheets automatically after planning.
- Sheet tiles carry more than a number: the sheet's filled-slot count, a `2×` badge for double-sided sheets, and an accent frame on the sheet currently displayed. The old strip had no current-sheet indicator at all, so on a long run there was no way to tell where you were without reading the toolbar counter.

- **Hot folders: the same content could be exported twice.** The ledger's "has this already been processed?" check and the reservation insert were two independent statements, so with `maxConcurrentJobs` above 1 two consumers could both pass the check for a file whose content had already been exported. The pair is now a single immediate transaction, and a unique index enforces it at the database level as well. Verified against a real database: eight concurrent attempts on an already-completed fingerprint now yield zero reservations, while thirty distinct fingerprints still proceed in parallel.
- **Hot folders: a data race could silently freeze the polling watcher.** The directory snapshot was a plain dictionary written concurrently by the polling loop and the start-up rescan for the whole life of a folder start. Concurrent writes to that type are undefined behaviour — in practice an exception, or an endless spin that pins a thread at 100% CPU with nothing in the log, surfacing as "the hot folder stopped seeing files".
- **Hot folders: a watcher could come back to life after being stopped.** The recovery path that rebuilds a `FileSystemWatcher` after an OS error did not check whether the folder had been disposed meanwhile, leaving an orphaned watcher holding a directory handle open — which also blocks a network share from being unmounted — and firing events into a dead pipeline.
- **Hot folders: one bad folder no longer breaks every reload, permanently.** A runner that failed to start aborted the whole configuration reload before the new configuration was published, leaving the internal state describing one generation and the runner list another. Every subsequent reload then failed outright until the application was restarted. Failures are now isolated per folder, as they always were on the initial start.
- **A locked `hotfolders.json` no longer stops the application from starting.** Only malformed JSON was handled; a file momentarily held open by a backup agent, antivirus or cloud sync propagated all the way out and exited the process with code 2 — before any window appeared, so the operator saw nothing happen at all.
- **PDF/X output intent could claim CMYK for an RGB or grayscale profile.** The ICC header was read with a call that is allowed to return fewer bytes than requested; the short read fell through to the CMYK default, producing a non-conformant file that passed our export and failed in the customer's RIP.
- **Grayscale conversion silently skipped images with a malformed `/Indexed` palette**, leaving colour artwork in a file that was supposed to be monochrome. The guard that the RGB converter already had is now applied here too.
- **A failed ICC profile load leaked a colour-system handle.** The constructor opened the sRGB profile first, so if the output profile was rejected the exception left the first handle open forever — no object existed to dispose it and there is no finalizer. A hot folder pointed at a bad profile leaked one handle per job, in a loop.

### Security
- **The sheet- and page-range fields could exhaust memory from a typo.** A range was expanded element by element with no limit, before any check against the document's page count could run: `1-20000000` — ten characters — allocated about 726 MB, and a slightly larger number ended the process. Ranges are now capped at 100 000 numbers with a clear message. Measured before and after.
- **Closed a path-traversal hole in marks profiles.** A template's `marksProfileRef` reached `Path.Combine` unchecked, so an imported template could point the read outside the profiles directory. Only saving validated the identifier; reading and deleting now do too, with the path builder itself as a last line of defence.
- **Updated dependencies with published advisories** — `System.Text.Json` to 8.0.5 (two high-severity) and `SQLitePCLRaw` to 3.0.4 / 3.50.3 (one high). Dependency auditing is now on for every build, in transitive mode, and the two advisories that have no available fix are listed explicitly so that anything **new** still fails loudly instead of being lost in a wall of known warnings.
- **Ghostscript is invoked through an argument list instead of a hand-quoted command line**, removing a class of bug around paths with spaces, UNC paths and trailing separators.
- **An environment variable can no longer downgrade the licence or telemetry endpoint to plain HTTP.** Those requests carry the machine fingerprint; only HTTPS, or loopback for development, is accepted.
- Both network services now share one HTTP client per process instead of creating one per request, which left sockets in `TIME_WAIT` and forced a fresh TLS handshake every time.

### Performance
- **Hot folder throughput: two WMI queries removed from in front of every job.** The per-job licence check re-read the disk serial and motherboard UUID each time — `Win32_DiskDrive` alone routinely costs hundreds of milliseconds, seconds on a machine with parked disks. A 500-file batch paid over a minute of pure overhead, and application start-up paid it again before the window appeared. Hardware cannot change while the process runs, so the fingerprint is cached; the licence signature and expiry are still verified for every job.
- **The same PDF is no longer parsed two or three times per export.** Analysis — the most expensive operation in the application — ran when the file was added, again for preflight and again inside the export pipeline. Results are now reused for as long as the file on disk is unchanged.
- **Colour conversion caches per-colour results.** Every `rg` operator in a content stream previously cost a separate call into the operating system's colour engine plus four array allocations; a real document uses a few dozen distinct colours.
- **Image conversion reads pixels by row rather than one at a time**, and decodes without the alpha channel it immediately discarded — 12 million redundant bounds checks and a 25% larger buffer on a single 4000×3000 photograph.
- **Diagnostics no longer read the settings file on every event.** The opt-out flag was loaded and deserialised from disk on each check, including from the UI thread.

### Removed
- The floating sheet strip and the `ShowSheetStrip` flag that gated it.
- Seven unused public members, among them the only renderer entry point that rasterised synchronously — it bypassed the concurrency gate, so any future use would have frozen the interface on a large page.
- Four directories that were created at every start and never written to, one of which implied support for custom language packs that does not exist.

### Fixed
